## 一、核实过的事实（本机实测，可复现）

### 1.1 沙盒子目录：权限允许，执行器失败

| 层 | 结论 | 证据 |
|---|---|---|
| 权限层 | ✅ 子目录本就允许 | `_scopeAllowed` 前缀匹配：`target === root \|\| target.startsWith(root + sep)` |
| 执行层 | ❌ 不建目标父目录 | `agent-transaction.js` 只对自己的 `dir`/`backupDir` 做 `mkdirSync` |
| 命名层 | ❌ 生成不出子目录路径 | D-27 的 `buildSandboxScope()` 拒绝 `/[\\/]/` |

实测三组（真实 `proposeInternal` → `confirm-action` → `executeInternal` 全链）：

| 目标 | 预建父目录 | 结果 |
|---|---|---|
| `flat.md` | — | ✅ 落盘 |
| `plans/deep.md` | 否 | ❌ `EXECUTION_FAILED` |
| `plans2/deep2.md` | 是 | ✅ 落盘 |

### 1.3 审计日志存不下长预览

`src/agent-interfaces.js:589`：任何字符串字段 > 500 字被截到 500。

且 `agent-audit.jsonl` 是**安全审计**（谁在何时请求了什么权限、被何理由拒绝）。观察记录是**行为数据**。混写会导致任一方改格式都波及另一方。

**结论**：另起 `agent-observations.jsonl`。

### 1.4 她读得到自己写过的东西

```
main.js → brain.askForSelfNote() 拿内容
  → proposeInternal(..., 'selfNote', content) 盖戳
  → 执行器 SELF_NOTE_EXEMPT 免确认直写
  → 关窗 _engraveSelfNotes() 铸进 experiences.jsonl
  → 下轮 memory._drainSelfNotes() 把内容注入尾部
```

**只要执行成功，她就读得到。** 只有「未执行（observe 档）」或「执行失败」时才需要特殊处理。

### 1.5 真实审计：她从未拒绝过立项

`%APPDATA%\life\agent-audit.jsonl`，30 条：

```
proactive-offer      | dispatched      21
agent:propose-action | accepted         3
agent:execute        | executed         2
agent:execute        | rejected         1
agent:execute        | failed           1
agent:confirm-action | recorded         1
chat-failed          | failed           1
```

`refused_by_subject` = **0**，`draft_unavailable` = **0**。

> `agent:execute | rejected` 那条不是拒案——是 D-19 事故化石：`selfNote` 本该免确认却亮卡，用户点【授权】→ `ALREADY_EXECUTED`。

**影响**：`refused` 回声暂无数据可回声。D-27 已把这两个 outcome 写进审计，一旦 `agentTriggerEnabled` 打开正常聊几次，数值就会变化——**这个「不做」的理由会自己失效，需定期复核。**

### 1.6 关键：程序目前无法知道「档位从 observe 变成了 auto」

我查了现有代码：

- `config.js` 有 `schemaVersion` / `configVersion`，那是**迁移版本**，不是配置变更历史
- **全仓没有** `prevConfig` / `lastConfig` / `configHistory` 任何机制
- `config.js` 启动时读一次，**没有文件变更监听**

**所以「观察期满补注入」不能靠比对配置实现**——启动时只看到当前是 `auto`，不知道之前是不是 `observe`。

**必须新增状态字段**（见 2.5）。

### 1.7 `memory.js` 加载路径会重建 `this.data`，新字段必须显式归一

`memory.js:263-290`：

```js
this.data = { ...默认值, ...data, nextMessageSeq: ... };   // spread 会带进新字段
this.data.lexicon = Array.isArray(...) ? ... : [];          // 显式归一
this.data.expectations = ...;                                // 显式归一
// selfNotes: filter + map + slice，逐条守卫
```

该段注释明确写着纪律：「旧档案缺字段 → 空表；脏数据 → 归一为数组（绝不静默丢历史）」。

**任何新字段必须在这里显式归一**，否则脏数据会导致注入时算出 `undefined`。

## 二、方案

### 2.1 要解决的真问题

> **以后每加一个「她自发会做事」的能力，我怎么在放它出去之前，先看她在没人时会怎么做？**

现在的二选一：免授权直接做（出事才知道）／每次都问她（毁掉自发性）。`observe` 是第三档。

### 2.2 三档与拦截水位线

| 档位 | 行为 | 拦截时机 | 落盘 | 记录 |
|---|---|---|---|---|
| `off` | 不评估 | 调 `brain.askFor*()` **之前** return（零 LLM 开销） | 否 | 否 |
| `observe` | 照常想、照常拟稿 | 拿到非空正文后、`proposeInternal` **之前** | 否 | 写观察记录（完整正文） |
| `auto` | 照常想、照常拟稿 | 不拦截 | 是（现状） | 审计 `executed`（现状） |

> **防空记录污染**：`observe` 档下若她在 `brain.askFor*()` 阶段自己决定不写（`refused` / `unavailable`），**不写观察记录**（仍按 D-27 原逻辑走）。保证观察文件里每一行都是完整成稿。

### 2.3 默认值：已有能力 `auto`，未登记能力 `observe`

```js
// src/config.js
const DEFAULT_AGENT_CAPABILITY_MODES = {
  selfNote: 'auto',
  observerJournal: 'auto',
};

function getCapabilityMode(config, capabilityKey) {
  const modes = (config && config.agentCapabilityModes) || {};
  const v = modes[capabilityKey];
  if (v === 'off' || v === 'observe' || v === 'auto') return v;
  return DEFAULT_AGENT_CAPABILITY_MODES[capabilityKey] || 'observe';
}
```

**要点**：未登记能力回落 `observe`（对齐 DeepSeek 原型 `default('observe')`）——以后加新能力，忘了配置也落在最安全档位。

**不把 `observe` 设为全局默认**：那是收权。`selfNote` / `observerJournal` 免授权是 D-17 用户拍板过的（`agent-executor.js:444`）。

### 2.4 观察记录：另起文件，完整正文，定长轮转

**文件**：`agent-observations.jsonl`，`app.getPath('userData')`，与 `agent-audit.jsonl` 同目录不混写。

```json
{
  "at": 1793600000000,
  "capability": "selfNote",
  "intentKind": "wantToLeaveSomething",
  "proposalSource": "selfNote",
  "scopeName": "note-2026-11-01-abcd.txt",
  "content": "（完整正文，不截断）",
  "contentBytes": 512,
  "wouldHaveExecuted": true,
  "reason": "observed"
}
```

**为什么存完整正文**：观察档唯一价值就是让人判断她写得对不对。给全文，让人自己看。**程序不去解析 Markdown**（`planOutline` 那种设计等于用正则猜自然语言——D-27 的拒案判据在同类事上错了四轮）。

**定长轮转 + 时间兜底**：`MAX_OBSERVATION_LINES = 100` 或 **最近 90 天**，先到先轮转。

> 🔵 **本段按真实数据修正（2026-11-01）**。原写 `200 条 / 按每天 1~2 条算约 100~200 天`，
> **那个频率假设比真实数据高一个数量级**。
>
> 实测 `%APPDATA%\life\memory.json` 里现有便签：**25 字 / 32 字**，共 3 条 / 25 天 ≈ **0.12 条/天**。
> 按这个频率，200 条要 **1666 天（4.5 年）**——远超任何合理的观察周期。
>
> **判据应该是「观察窗口需要几个样本」，不是「能存多久」**：
> - 判断一个新能力跑得好不好，**30~50 条**就够
> - 100 条已留足余量
> - 存多久由 **90 天**时间维度兜底（防止低频能力永远填不满、也防止高频能力几天滚完）
>
> ⚠️ **重要前提**：这个频率是**便签**的频率。若观察的是新能力（如「主动整理沙盒」），
> 产出可能高两个数量级——那时 100 条会在几天内滚完。所以**时间维度不是可选项，是必需的**。

### 2.5 🔴 观察期状态与「期满一次性补注入」

**这是本方案最核心、也是前序文档都没解决的部分。**

#### 产品语义

| 问题 | 答复 |
|---|---|
| 观察期里她想过的念头，算不算她的经历？ | **算。** |
| 算经历，就要实时注入给她吗？ | **不要。** |
| 那怎么处理？ | **观察期不注入；期满一次补齐。** |

**「动作史是事后可查，注入是当下告诉她」**——前者不需要她知道，后者才涉及观察者效应。

#### 状态字段（必须新增）

```js
// memory.data 新增，且必须在 :263-290 那段显式归一
memory.data.observeEpoch = {
  // 键 = capability，值 = { enteredAt, leftAt, pendingEcho }
  //   enteredAt   进入观察的时刻
  //   leftAt      离开观察（切回 auto）的时刻，null = 仍在观察期
  //   pendingEcho 待补注入标记，true = 还没补过（见下方"双通道"）
};
```

**加载归一（必须照 `selfNotes` 的纪律写）**：

```js
// 旧档案缺字段 → 空对象；脏数据 → 归一为对象
if (!this.data.observeEpoch || typeof this.data.observeEpoch !== 'object') {
  this.data.observeEpoch = {};
}
```

#### 触发点：**双通道，问句优先，对话兜底**

> 🔵 **本节按审阅意见修订**。原方案只说「下次拟稿成功时」，漏了一个场景：
> **若她切到 `auto` 后很久都不产出正文**（`askForSelfNote` 要「挂机 120 分钟 + wantToLeaveSomething」才触发），
> 观察史会一直悬着；而这一周里她**已经能做事了**——一旦她真写了新便签，
> 就会出现「新便签已进 `selfNotes` 并注入，旧观察史还没补」的**顺序与语义错乱**。
> 这与 2.5 自己要解决的问题是同一类：**记忆断层**。

**两个通道，按优先级：**

```
① 首选：她下次产出合法正文（askForSelfNote / askForProposalContent 成功）
     → 语境最贴切（她正在「想写点什么」），注入进**那次独立调用**的 prompt
② 兜底：任何一次 memory.build() 常规对话
     → 若 observeEpoch[cap].leftAt 存在且 pendingEcho 标记未消费
     → 注入进**常规对话尾部**（不是 system，护缓存）
     → 消费后清标记
```

**实现要点：**

```js
// leftAt 写入时，同时置一个待补标记
memory.data.observeEpoch[cap] = { enteredAt, leftAt, pendingEcho: true };

// ① 独立调用路径（askForSelf*）优先消费
// ② memory.build() 每次检查：若有 pendingEcho 且本轮未在独立调用中 ⇒ 走兜底
```

⚠️ **为什么问句优先**：语境贴切。她在「想写点什么」的时候看到「那段时间你想过这些」，语义连贯；而在普通闲聊里突然弹出这段，会显得突兀。

⚠️ **为什么必须有兜底**：**宁可语境稍差，也不能让她的记忆出现「新的已经在了、旧的还没补」的断层。**

⚠️ **注入位置必须区分两条路：**

| 通道 | 注入到哪 | 缓存影响 |
|---|---|---|
| ① `askForSelf*` 内部 | **那次独立调用**的 prompt | 零影响（独立调用不走常规前缀） |
| ② `memory.build()` 兜底 | **对话尾部**（与 `bedside` / `selfNote` / `reunion` 同挂点） | **绝不进 system**，护前缀缓存 |

🔴 **实现禁区**：兜底通道**绝不能**把注入文本写进 `memory.build()` 的 system 部分。那会破前缀缓存不变式（**实测过的铁律**：95%+ 命中率会掉）。只许进尾部。

#### 🔴 措辞必须带原因（前序方案两处都栽在这里）

**错的写法**（无因，模型会读成「我失败了」）：

> 「最近你有过几次想写点什么的念头，都没有落成文件。」

**对的写法**（说明为什么，且只陈述系统状态）：

> 「那段时间里，你有过几次想写点什么的念头，当时还没有开放落成文件——**不是你失败了，是那时候我还不能让你存下来**。现在可以了。」

**关键**：把「不是你的问题，是程序限制」说清楚。这句话消掉「我失败了」的误读，而且它是**事实**，不需要编造。

#### 一次补多少

观察满期可能有几十条。**不能全灌**。最终形态：**只给计数 + 原因，不给文件名、不给时间范围。**

```
「那段时间里，你有过几次想写点什么的念头，当时还没有开放落成文件——
 不是你失败了，是那时候我还不能让你存下来。现在可以了。」
```

> 🔵 **本段按审阅与真实数据修正（2026-11-01）**，改掉三处：
>
> | 原来 | 改成 | 理由 |
> |---|---|---|
> | 「17 次」这种精确数字 | 「几次」 | 真实频率 0.12 条/天，一个月仅 3~4 次。**精确数字会放大语义权重**，让 3 次读起来像很频繁 |
> | 「我还在观察**你的判断**」 | 「还没有开放落成文件」 | **「观察你的判断」把她放到了被评估的位置**，像是 KPI 考核。改版只陈述系统状态，不做人格评价 |
> | 「从（某时节）到（某时节）」+ 三个文件名 | **全部删除** | ① 时间是信息，与 `WANT_TO_LEAVE_SYS`「你不知道现在几点」铁律冲突；② **陌生文件名会被理解成「我欠了三个文件没写」**，正是要避免的「补救执念」触媒 |
>
> **若她真想回看具体想过什么**：那是**动作史投影（第 2 步）**要解决的问题——让她自己查，而不是塞给她。

⚠️ **不写具体日期钟点**（与 `WANT_TO_LEAVE_SYS` 铁律一致：不暴露时钟）。用「那段时间」这类定性表述。

### 2.6 不回流进 `selfNotes` 队列（独立队列）

**历史问题**：`memory.js:1217` 的 `shift()` 与 `:290` 的 `.slice(-8)` 无差别丢最旧，`SELF_NOTE_MAX_QUEUE = 8`。若把观察条目塞进 `selfNotes`，会**挤掉真实落盘、已铸自传的正式便签**。

**方案**：**独立队列，物理隔离**。

```js
memory.data.observedNotes = [];   // OBSERVED_MAX_QUEUE = 5
```

> 🔵 **上限按真实数据修正（2026-11-01）**：原写 20，改为 **5**。
> 依据：该队列的**唯一用途**是期满时做示意（见 2.5「一次补多少」），**不注入、不铸自传、不给动作史读**
> （动作史读的是 `agent-observations.jsonl`）。
> 按真实频率 0.12 条/天，**20 条要 166 天才填满——等于永远没有上限**。
> 5 条已足够覆盖需求，且各版本改措辞后**连文件名都不再输出**，实际只需保证队列不无限增长。

**好处**：
- 不可能挤占 `selfNotes`
- `selfNotesToEngrave()` 完全不用改（它只看 `selfNotes`）
- 清理逻辑独立，不碰 D-24 铸造幂等
- **不注入链路**（见 2.5，观察期内不注入），所以连 `drained` 标记都不需要

## 三、明确不做的

| 不做 | 理由 |
|---|---|
| **重型总监外壳**（Blueprint / MandateTicket / Handback / 工单唤醒） | 见第五节。记忆地基未打起之前造工单格式，是空中楼阁 |
| 加 `workspace.writeBlueprint` / `writeTicket` 新能力 | 要动 4 处安全边界（`agent-ipc.js` 实为 12 处判定），而平铺 `.md` 用现有 `workspace.write` 就够 |
| `planOutline` 结构化解析 | 用正则猜自然语言。存完整正文更可靠 |
| 观察记录进 `agent-audit.jsonl` | 安全审计与行为数据必须分开；500 字截断存不下正文 |
| 把 `observe` 设为全局默认 | 收权。D-17 拍板过 `selfNote` / `observerJournal` 免授权 |
| 现在做 `refused` 回声 | 真实数据 0 次。功能没错，但无数据可回声（1.5），且该前提会失效（1.6 同款时效问题） |
| **观察期内实时注入** | 观察者效应 + 重试执念 + 削弱动机（见 2.5） |

## 四、演变历史（为什么走到这一步）

记录关键转折，避免后来者重复踩坑。

### 4.1 误杀四轮（D-27 的拒绝判据）

同一类**误杀**在 D-27 上出现过四次，每次都以为找到根因：

| 轮次 | 判据 | 被误杀的内容 |
|---|---|---|
| D-5b | `startsWith('不')` | `不做X` / `不写入X` / `不记录X` |
| D-5c | `includes('先放一放')` | `先放一放搜索`（短语在名词前） |
| D-5d | `endsWith('先放一放')` | `搜索放一放`（名词在短语前） |
| 最终 | **短语前有无实义宾语** | — |

**教训**：`这个先放一放`（拒绝）与 `搜索放一放`（延期）**文本结构完全一样**。**加词表治不了这个病，换判据方向才行。**

⚠️ **这个教训直接支撑本方案 2.4 的「不做 `planOutline`」**——让程序解析 Markdown 结构，会重蹈覆辙。

### 4.2 「拿断点当先例」（本轮）

早期方案 3.3 论证「observe 档不回流」时，用 `main.js:469` 决策 4（写失败不告诉她）当先例。

但那份设计在 `docs/PROPOSAL-AGENT-HISTORY.md` 第 62-73 行被明确列为**断点 2**：「制造了认知与事实不符的缺口」。

**用自己认定为问题的东西论证新设计，推理是坏的。** 本方案的 2.5 修正了这一点。

### 4.3 「观察者效应」的边界（本轮）

观察者效应只能推出：

> 不要让她知道「我的念头被记录下来」。

推不出：

> 不要让她知道「我有过想法但没写成」。

**前者是观察的纯度，后者是记忆的事实性。** 这个区分是本方案 2.5 的基础。

## 五、为什么砍掉「总监外壳」

1. **「总监」是一段关系，不是一个文件格式。** 她得先知道上次提了什么、你为什么拒、后来改成什么——这些全是**记忆**，不是 JSON 模板。

2. **现有 `workspace.write` 已经够写方案。** 1.1 实测证明平铺 `.md` 完全能落盘。记忆地基打好后，她用现有能力写平铺 `.md` 即可，**不需要突破五道闸门加新能力**。

3. **DeepSeek 的 Mandate / Ticket 是为「一个团队一个仓库」设计的。** 初澜没有 Source、没有 Thread、没有多人协作。

4. **概念数量超过问题数量。** 总监方案要 8 个概念（`DirectionEval` + `Blueprint` + `MandateTicket` + `Mandate` + `Handback` + `TicketResumption` + 双轨制 + 四核心）解决 1 个问题；`observe` 用 1 个概念解决同一个问题。这违反它自己引用的 `docs/000-philosophy.md`「只引入工作真正需要的最少概念」。

5. **「约束即护城河」的推论不成立。** 被禁 `process.execute` 只说明她**不能当程序员**，推不出她**能当总监**。后者需要方向判断力、上下文记忆、跨会话连续性——都没有。用「我做不到 A」论证「我适合做 B」是逻辑跳跃。

## 七、验证方式（全量真跑，拒绝恒真断言）

1. **单测** `test/agent-observe-mode.test.js`
   - 三档分流：`off` 在调 LLM 前跳过 / `observe` 拟稿但不调 `proposeInternal` / `auto` 保持现状

   - **队列保护断言**：连续产 N 条观察记录后，`memory.data.selfNotes` **逐字节不变**
   - **期满补注入断言**：`observeEpoch.leftAt` 存在时注入一次，注入后清空；第二次不重复注入
   - **双通道断言**：① 若先发生 `askForSelf*` 成功 ⇒ 走该独立调用；② 若先发生常规对话 `memory.build()` ⇒ 走尾部兜底；两条路径**都只补一次**，且消费 `pendingEcho` 后不再触发
