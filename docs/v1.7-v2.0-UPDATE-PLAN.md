## 3. v1.7：进得来 + 看得见

### 3.1 v1.7-a：STT 语音输入（中文 / 英文）

#### 3.1.1 目标

用户**说话代替打字**。识别出的文字填入输入框，**由用户确认后再发送**（默认不自动发送）。她**不出声**——本版只做输入。

#### 3.1.2 三条候选路线（**需你拍板，这是本版最关键的决策**）

| 档 | 方案 | 可行吗 | 优点 | 代价 |
|---|---|---|---|---|
| **A** | Web Speech API（`SpeechRecognition`） | ⚠️ **高度可疑，须首日实测** | 若可用则零依赖、零密钥 | Chromium 的语音识别依赖其内置云服务与密钥，**Electron 通常不带**；据已知实现不可用，但**我没在本机实测过，不作断言** |
| **B** | 云端 STT（OpenAI 兼容 `/v1/audio/transcriptions`，如 Whisper） | ✅ 可行 | 中英识别质量稳定；复用既有 Provider / 凭据体系 | 需网络 + 一份 STT 密钥；需新增 multipart 传输（现有 `openai-transport.js` **无 multipart / FormData**） |
| **C** | 本地模型（whisper.cpp / node-whisper） | ✅ 可行但重 | 完全离线、隐私最好 | 要分发二进制 + 模型（数百 MB）；`dependencies` 目前为空，引入即破「零运行时依赖」现状 |

**我的建议：B 打底，A 作为首日可行性探测。**

理由：
1. **A 必须先验**（半天工作量）：如果能用，就是零成本方案的巨大胜利；不能用也不亏，只花半天。
2. **A 不可用时走 B**：项目已经有完整的 Provider / 凭据 / 端点校验体系（`provider-policy.js` 的 `validateCredentialTarget`），STT 是它的自然延伸，不是新体系。
3. **C 明确不做**：为一个输入功能引入数百 MB 模型分发，与「桌面常驻轻量软件」定位冲突；且它会让发布包从当前的体积量级直接膨胀一个数量级。

> ⚠️ **更正（2026-10-19，用户指出）**：本文档初稿在此处写了「它和 760×1000 管线抢同一台 GPU 台式机」——**这句是错的，已删除**。
> 实测：`assets/character/` 下**全部 34 个图层均为 64×80**（`base.png` 也是 64×80）；760×1000 只剩 `assets/character-archive-760x1000/` 里 7 张**已淘汰归档** + `base_legacy_full.png`，两者都被 `asar-check.js:53` 的 `RETIRED_PATTERNS` 挡在包外。
> 当前正典立绘是**像素级 64×80**，760×1000 是**上一代已退役方案**。详见 §10。

> ⚠️ **诚实边界**：A 档我的判断来自「Chromium 语音识别依赖 Google 内置服务」这一已知事实，**但我没有在本机跑过 `SpeechRecognition`**。施工第一步就是写一个最小探测页验证，`onerror` 是否为 `network` / `service-not-allowed` 即可定论。**在实测前不要把 A 写进任何承诺。**

#### 3.1.3 铁律

1. **识别结果一律进输入框，由用户确认后再发，绝不自动发送。**
   理由：语音识别必错（尤其专有名词、中英混说）。自动发送 = **程序替用户说话**，会污染 `memory.history` 里「用户真实说了什么」这条事实链。
2. **麦克风权限必须是显式白名单，不能靠默认。**
   实测 `main.js` **没有 `setPermissionRequestHandler`**。Electron 在不设处理器时对权限请求的放行策略不可依赖——**本版必须显式加一个「默认拒绝、只放行主窗口的 `media`」的处理器**。这是一条安全加固，不只是 STT 的前置。
3. **音频绝不落盘。**
   采集 → 送识别 → 立刻丢弃。任何"留一份便于调试"都是隐私事故。
4. **识别失败静默，只写审计。**
   断网 / 无麦克风 / 权限被拒 → 输入框旁一行客观提示（如「没听清」），**不弹 Modal、不打断对话**。
5. **零耦合**：`brain.js` / `memory.js` / `trigger.js` / `subject-state.js` **一个字节不改**。STT 是渲染层 + 主进程 IPC + 一个传输模块。

#### 3.1.4 实施面（预估）

| # | 位置 | 改什么 | 性质 |
|---|---|---|---|
| 1 | `main.js` | 新增 `setPermissionRequestHandler`（默认拒、只放行主窗口 `media`） | **安全加固，需你确认** |
| 2 | `main.js` | STT IPC：接收音频 buffer → 调 STT 端点 → 返回文本 | 新增 |
| 3 | 新建 `src/stt-transport.js` | multipart 上传 + 端点校验（复用 `provider-policy` 的白名单思路） | 新增 |
| 4 | `preload.js` | `sttTranscribe(audioBuffer, { lang })` | 新增 |
| 5 | 渲染层（`pet.js` / `chat.js`） | 按住说话 / 点击开始停止、MediaRecorder、把文本塞进输入框 | 新增 |
| 6 | `index.html` / `chat.html` | 麦克风按钮 | 新增 |
| 7 | `ui-i18n.js` | 中英双语文案（含权限被拒、无麦克风、识别失败的客观提示） | 新增 |
| 8 | `test/v17-stt.test.js` | 门禁 | 新增 |

#### 3.1.5 验收判据

1. 说一句中文 → 输入框出现中文文本；说一句英文 → 出现英文；**均不自动发送**。
2. 权限被拒 → 一行客观提示，**不抛异常、不弹 Modal**，对话功能完全不受影响。
3. 断网 / 密钥无效 → 同上，**静默降级**。
4. **音频零落盘**：门禁断言临时目录里没有任何新音频文件（含 `.webm` / `.wav` / `.ogg`）。
5. **历史零污染**：STT 前后 `memory.build()` 的 system 与 history 快照逐字节相等。
6. 权限处理器**默认拒绝**：未在白名单里的 `media` 请求一律 `deny`（有独立断言）。
7. 全量套件 0 FAIL；README 测试块项数同步。

#### 3.1.6 本版不做

| 不做 | 理由 |
|---|---|
| TTS（她出声） | §1 裁决 |
| 语音唤醒词（"初澜"） | 常驻监听是高隐私风险，且误触发率不可控 |
| 流式边说边转 | 先做「按住说完再转」；流式是独立的打断/尾音难题 |
| 多语种（中英之外） | 用户已定：先中英两版 |
| 把识别结果直接喂给 Brain | 必须先经输入框让人确认 |

### 3.2 v1.7-b：个体观测面板补全（模块注册表化）

#### 3.2.1 问题（实测）

现状 `main.js:1242-1290` 的 `life-mechanisms` 只返回 **6 组**，`pet.js:780-841` 只渲染这 6 组：

```
lexicon（词汇表）/ expectations（预期账本）/ vitals（生理潮汐）
/ development（发育景观）/ cognition（认知张力）/ relations（关系与存在）
```

但 v1.1 ~ v1.6 陆续落地的机制**大量数值已经存在、却完全看不到**：

| 已产出但未暴露的数据 | 数据所在（实测） | 影响 |
|---|---|---|
| **心境（warmth / stillness）** | `internal-regulation.js:283` 的 `getMood()` 存在，但 `getState()` **不含它**，handler 也没取 | 48h 慢变心境完全不可见 |
| **互动密度 / 认知负荷 / 显著性阈值** | `getState()` 返回 `interactionDensity / cognitiveLoadProxy / salienceThreshold`（`:294-300`），handler 只取了 `energy/restPressure/arousal/isSleeping` | v1.0.7 的社交密度体感带不可见 |
| **主动开口意愿偏置 `initiativeBias`** | `trigger.js:104` 每次 `updateTraits` 都会重算 `this.initiativeBias`，`:110` 只是把它当返回值返回，**没有任何读取入口**（全仓 grep `getInitiativeBias` 零命中）。纯函数 `computeInitiativeBias` 是导出的，可直接用 `subjectState.values` 复算 | 特质如何影响搭话频率不可见 |
| **好奇队列 `curiosityQueue`** | `memory.data.curiosityQueue`（上限 5 条，`memory.js:658-661`） | D-25 好奇破冰的真实待问队列不可见 |
| **自发便签 `selfNotes`** | `memory.data.selfNotes`（含 `drained` / `engraved` / `source` 状态） | D-13/D-20/D-24 整条链不可见 |
| **观察日记 `observerJournal`** | `memory.data.selfNotes` 中 `source==='observerJournal'` 的子集 | v1.4 生命观察日记不可见 |
| **记忆印痕分层（ACTIVE/FADING/DORMANT）与召回计数** | `engramManager.getDormantTraces()/getFadingTraces()`（`memory.js:436-437`）存在，但**没有统计入口**；D-23 的 `retrievalCount` 无面板 | 三层记忆的"遗忘退行"完全不可见 |
| **熔断器状态** | `brain.providerBreaker.getState()`（`circuit-breaker.js:59` 返回 `{ state }`） | v1.5 容灾熔断状态不可见 |
| **知觉事件水位线** | `getState().watermark`（`runtimeCachedCount / persistedCount`） | 具身知觉的消费进度不可见 |
| **缓存命中率** | stats 面板有（`pet.js:1641+`），但**不在个体观测** | 观测与统计割裂 |
| **Agent 通道**：审计、执行预算余额、沙盒清单 | `main.js` 的 `agentAuditLog` / `ExecutionBudget`，grep 无面板出口 | v1.0 五道闸门不可见 |

**结论：这不是"加几个字段"，是缺一张「可观测性清单」。** 每次新增机制都靠人记得去改 handler 和 UI —— 一定会漏（D-23 召回计数就是活证据）。

#### 3.2.2 方案：声明式模块注册表

新增 `src/observability.js`，导出一张**声明式**清单：

```js
// 每项只声明「怎么读」，不声明「怎么画」——
// 渲染层按 group 自动分块，新增机制只需注册一行，不可能漏。
{
  id: 'vitals.mood',
  group: 'vitals',
  labelKey: 'obs.mood',
  read: (ctx) => ctx.internalRegulation.getMood(),   // 返回 { warmth, stillness }
  fields: ['warmth', 'stillness'],
  unit: null,
  range: [-100, 100]      // 供渲染层画条形；null = 纯文本
}
```

- `main.js` 的 `life-mechanisms` 改为**遍历注册表**产出，不再手写字段；
- `pet.js` 的 `refreshLifeMechanisms` 改为**按 group 动态生成区块**，不再手写 `setLines('rVitalsList', ...)`；
- 每项 `read()` 必须**只读、不推进任何内部时钟**（照 `getMood()` 头注释的既有纪律）。

#### 3.2.3 铁律

1. **只读。** 注册表里任何 `read()` 都不得推进时钟、不得消费队列、不得落盘。违反会让"打开观测面板"本身改变她的状态——那是**观察者效应污染实验**。
2. **绝不造假。** 数据缺失给 `null`，渲染层显示破折号（沿用 `main.js:1265` 的既有做法），**不许补零、不许估算**。
3. **绝不外泄主体私有内容到导出。** 便签正文属主体经历，面板可显示「有条数 / 哪一类 / 是否已注入」，**正文默认不展开**；要展开必须走既有的研究导出链路（那是已被审计的边界）。
4. **零写入**：整条链路不许出现 `save()` / `append()`。

#### 3.2.4 验收判据

1. **覆盖断言**：注册表里每一项在开启观测后都返回**非 `undefined`**（`null` 合法，表示真的没有）。
2. **死项守卫**：注册表的 `id` 与渲染层实际生成的区块**双向差集为空**（照 `public-export.js` 的 `deadRules` 手法），防"注册了但没画"和"画了但没注册"。
3. **观察者效应断言**：连续调两次 `read all`，所有数值**逐字节相等**（除时间戳类字段），证明只读不推进。
4. **不造假断言**：构造一个缺数据的上下文，面板出现破折号而**不是 0**。
5. 全量套件 0 FAIL；README 项数同步。

#### 3.2.5 本版不做

| 不做 | 理由 |
|---|---|
| 把观测数据画成图（折线 / 星云） | 那是 v1.9 看板；v1.7 只做「数值看得见」 |
| 观测面板写操作（改特质 / 重置状态） | 观测层必须纯只读，写操作走各自既有通道 |
| 新增可写入的调试接口 | 同上 |

## 4. v1.8：时间与视觉（两条新感知）

### 4.1 v1.8-a 重逢心境（主观时间）

**现状**：只有 45/90 分钟静默阈值，无"离开多久"的跨重启事实。

**方案**：持久化 `lastSeenAt`，离开超过独立阈值（建议 **≥ 6 小时**，与 30/45/90 分钟静默搭话**完全解耦**）时，把「你离开了 N 小时」作为**客观事实**挂到当轮尾部 —— 与 `_bedsideNote` / `_drainSelfNotes` **同一个挂点**（`memory.build()` 的 tail）。

**铁律**：
- 只陈述时长事实，**绝不加"我一直在等你"**（撞 `persona.js:29`「不虚构寂寞/苦苦等待」）；
- 一次性（挂过即消，与 D-13 同款）；
- 不进 system、不进 history（照 D-13 的快照断言）。

**存储位置（需拍板）**：建议 `stats.json`（运行统计，不属于记忆内容）。

### 4.2 v1.8-b 屏幕局部视觉探针

**这是本阶段风险最高的项**，因为它是唯一要同时动三层的功能：

| 前置 | 现状（实测） |
|---|---|
| Provider 能力标记 `vision` | `provider-registry.js:80` / `:97` **全部 `false`**，且无写入路径 |
| 传输层多模态（`image_url` / data URL） | `src/adapters/` 两个适配器 grep `image_url / multipart` **零命中** |
| 截图能力 | `desktopCapturer / capturePage` **零命中** |
| 隐私策略与审计口径 | 全新，无先例 |

**方案要点（草案，施工前须单独立项评审）**：
- **只在用户显式唤起时截**（快捷键 / 菜单二次点击），**绝不后台定时截屏**；
- 主进程 `capturePage` 局部区域 → 等比缩放到固定边长 → **只存在内存** → 转 data URL 送模型 → **用完丢弃，绝不落盘**；
- 结果只进**当轮尾部**（同 D-13 挂点），不入历史、不入经历；
- 审计只记「截了一块 w×h、耗时 x ms」，**不记任何像素内容、不记 OCR 文本**；
- 默认关闭 + 首次使用二次确认。

**诚实边界**：目标 Provider 若无 vision 通道，**本项整体降级为"不做"**，把该版本让给 v1.9 看板。**不要为了做功能去伪造多模态。**

## 10. 事实更正登记：立绘口径（2026-10-19）

本节是**纠错记录，不是新方案**。初稿两处出错，原因是我读了 ROADMAP §6.7 与三处陈旧注释后没回头核对资产实测。

### 10.1 实测事实

| 项 | 实测 |
|---|---|

| `assets/character-archive-760x1000/` | **7 个 PNG**，上一代归档 |

**结论：当前正典立绘是像素级 64×80；760×1000 是已退役的上一代方案，不参与任何运行时路径。**

### 10.2 ROADMAP §6.7 的准确读法

§6.7（`ROADMAP…md:474-478`）原文写的是 760×1000 切片管线，但同时写明：

> **当前过渡方案**：像素级切片资产顶班（已上线，像素取证通过…）；像素级资产按同路径整体替换，**代码零改动**。

即：§6.7 是「整图 → 切片」这条**通用管线**的设计，760×1000 是它当时的画布口径；而**实际顶班的是像素级，且像素级已是正式资产**。初稿把「管线里的旧画布口径」当成了「当前立绘规格」，是读文档不读代码的错。
