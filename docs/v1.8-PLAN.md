## 1. v1.8-a：重逢心境（主观时间）

### 1.1 核心理念：重逢是「关系事件」，不是「进程事件」

> 🔴 **关键纠偏（2026-10-20 核实定案）**：
> 桌宠的核心使用形态是**后台常驻（hide 不销毁）**，绝大多数时候进程不重启（如上班、外出、睡觉 8 小时，电脑不关机）。
> 若按“重启触发”，日常真正需要的重逢场景将永远不会触发。
> **重逢是人与她之间的互动间隔，不是操作系统的进程存活时间。**
> 无论中间进程是否重启，只要「距上次见到你」超过阈值，下次开口说话时就该感知到。

### 1.2 在场定义：什么时候算“见到你”？

| 事件 | 算不算“见到” | 处理 | 理由 |
|---|---|---|---|
| **发消息（`chat-send`）** | ✅ **算** | 更新 `lastSeenAt = now` | 最明确的在场互动 |
| **点她/拖她（物理互动）** | ✅ **算** | 更新 `lastSeenAt = now`（带 1 分钟写盘节流） | 真实触碰与陪伴 |
| **打开对话窗但没说话** | ❌ **不算** | 不更新 | 探头看一眼不算正式见面 |
| **应用启动** | ❌ **不算** | 不更新（除非冷启动无记录） | 进程活了 ≠ 人在电脑前 |

### 1.3 与现有阈值的解耦（**本版最关键的边界**）

现有三个阈值都是「**多久没互动就开口**」；重逢是「**这次离开有多长**」。两者**必须完全独立**：

| 机制 | 触发条件 | 行为 |
|---|---|---|
| 静默搭话（既有） | 30 / 45 / 90 分钟 | 她开口说一句 |
| 好奇破冰（既有，D-25） | 30 分钟 + 40 分钟节流 | 她问一个未解的问题 |
| 自发便签（既有，D-17） | 120 分钟 | 她写一张纸条 |
| **重逢（新）** | **≥ 6 小时** | **不说"我等你"，只陈述客观时长** |

> ⚠️ 若把重逢阈值设在 120 分钟以下，它会与自发便签争夺同一个窗口 —— 这正是 v1.5 当初归档本项的理由。**≥ 6 小时是硬下限。**
> 晚 11 点睡到早 7 点（8 小时）会触发「你离开了 8 小时」，只陈述事实，**绝不推断「你睡得好吗」**（程序不知道你是睡觉还是通宵）。

### 1.4 分步施工（共 4 步）

#### 第 1 步：持久化 `lastSeenAt` 与冷启动守卫

**存储位置**：`stats.json`。
**写入点**：
- 每次 `chat-send` 成功；
- 每次物理互动（`tracker.js`，1 分钟写盘节流）；
- 应用退出（`before-quit`，强制刷盘一次）。

🔴 **冷启动 / 首次运行守卫**：
若 `stats.json` 中 `lastSeenAt` **不存在**（新用户首次安装，或老存档首次升级）：
- **绝不注入任何事实行**（防止新用户开局被「你离开了 20 年」吓到）；
- 仅把 `lastSeenAt` 初始化为当前时间 `Date.now()` 并持久化。

#### 第 2 步：计算并生成事实行（分级粒度）

计算时机：**用户下次在对话框发消息那一刻（`chat-send`）回头检查**。

```js
const awayMs = now - lastSeenAt;
if (awayMs >= REUNION_MIN_MS) { // 6 小时
  // 分级格式化
}
```

| 离开时长区间 | 注入事实行格式 | 示例 | 理由 |
|---|---|---|---|
| **6 小时 ≤ t < 24 小时** | `【你离开了 N 小时】` | `【你离开了 8.5 小时】` | 一日之内的精准客观刻度 |
| **1 天 ≤ t < 7 天** | `【你离开了 N 天 M 小时】` | `【你离开了 3 天 4 小时】` | 跨数日的复合刻度 |
| **t ≥ 7 天** | `【你离开了 N 天】` | `【你离开了 12 天】` | **不带小时**，超长离开带小时失真机械 |

#### 第 3 步：挂到当轮尾部

**挂点必须复用 `memory.build()` 的 tail**（`memory.js:1132`），与 `_bedsideNote` / `_drainSelfNotes` 同级：

```js
const tail = [bedsideNote, selfNote, reunionNote, suffix].filter(Boolean).join('\n\n');
```

🔴 **顺序**：bedside（用户留的）→ selfNote（她自己写的）→ **reunion（客观时间事实）** → suffix。

#### 第 4 步：一次性消费

挂过一次即消费（`lastSeenAt` 更新为当前时间），同一次离开绝不重复提醒。

### 1.5 铁律

1. **只陈述时长，绝不加情绪，绝不推测行为。**
   - ✅「你离开了 8.5 小时」
   - ❌「我等了你 8 小时」—— 撞 `persona.js:29`「不虚构寂寞/苦苦等待」
   - ❌「你终于回来了」—— 是抒情，不是事实
   - ❌「你睡得好吗 / 通宵辛苦了」—— 程序无从得知人类生理活动，禁止主观推测
2. **不进 system、不进 history。** 照 D-13 的快照断言。
3. **一次性**，发过一次后立即消费。
4. **≥ 6 小时硬下限**，不与任何既有阈值重叠。
5. **冷启动无记录绝不注入**。

### 1.6 验收判据

1. **常驻不重启测试**：不重启应用，伪造 `lastSeenAt` 为 8 小时前，用户发消息 → 当轮尾部出现 `【你离开了 8 小时】`。
2. **进程重启测试**：退出再启动，伪造 `lastSeenAt` 为 8 小时前，用户发消息 → 同样正确出现。
3. **冷启动守卫测试**：`lastSeenAt` 缺失时发消息 → **不出现任何注入**，且 `stats.json` 被初始化。
4. **阈值下界测试**：伪造为 3 小时前 → **不出现**（与 120 分钟自发便签互不干扰）。
5. **分级粒度测试**：
   - 8.5 小时 → `【你离开了 8.5 小时】`
   - 76 小时（3天4小时）→ `【你离开了 3 天 4 小时】`
   - 12 天 → `【你离开了 12 天】`（不带小时）
6. **物理互动刷新测试**：点她/拖她更新 `lastSeenAt`，稍后发消息不触发跨度误判。
7. **一次性消费与缓存不变式**：连续两次发消息，第二次不出现；system 与 history 逐字节相等。
8. **禁句表断言**：注入文本不得含「等」「终于」「寂寞」「睡」「醒」等词。
9. 全量套件 0 FAIL。

### 1.7 已拍板（2026-10-20 四项裁决全部定稿）

| # | 决策项 | 裁决结果 |
|---|---|---|
| 1 | **触发点** | **用户下次开口说话时回头检查**（关系事件，覆盖常驻与重启） |
| 2 | **在场定义** | **发消息 + 物理互动算；打开窗口/进程启动不算** |
| 3 | **阈值** | **6 小时**（纯客观时长，不推断作息） |
| 4 | **冷启动** | **缺失时不注入，初始化为当前时间** |
| 5 | **分级粒度** | **<24h 显小时、1-7天 显天+小时、>7天 只显天** |

## 2. v1.8-b：屏幕局部视觉探针

### 2.1 三个必须先回答的问题

#### 问题一：目标 Provider 有 vision 通道吗？

> 🔴 **事实更正（2026-10-20 实测，推翻旧结论）**
> 旧版这里写着「DeepSeek 官方 V3/R1 均为纯文本，直接发图必报 400」—— **那是过期信息**。
>
> **实测结果**（用用户真实 Key、真实模型 `deepseek-flash`）：
> - 带 `image_url` 的 Chat Completions 请求 → **HTTP 200**
> - 发一张 1×1 红色 PNG 问「什么颜色」→ 回复 **「粉色」**（确实看图了）
> - `prompt_tokens: 223`（纯文本只有几十，多出的就是图片 token）
>
> **官方文档确认**（[Vision | DeepSeek API Docs](https://api-docs.deepseek.com/guides/vision)）：
> `deepseek-flash` 接受图文混合输入，支持 JPEG / PNG / GIF / WebP，
> **格式按文件内容判定**，不看文件名或声明的 MIME。
> `deepseek-v4-pro` 仍是纯文本（发图返回 400）。

**因此本项从「需另配 Provider」降级为「零新增成本」**：
用户现有的 `deepseek-flash` 就能看图，不必再申请 Key。

但仍必须做到：

| 要求 | 说明 |
|---|---|
| **能力前置校验** | 按模型名判断（`deepseek-flash` 支持 / `deepseek-v4-pro` 不支持），**不靠试错** |
| **UI 置灰 + 明确提示** | 当前模型无 vision 时，「看看这个」按钮**置灰**，提示「当前模型未开放视觉多模态能力」 |
| **绝不假装"她看过了"** | 无 vision 却送图 → 必须**显式失败**并告知用户，禁止静默丢掉图片后继续对话 |
| **token 成本预警** | 实测一次看图 `reasoning_tokens` 约 327、总计约 550 token。**看图比纯文本贵一个量级**，须在审计里留痕 |

#### 问题二：截什么？

| 粒度 | 做法 | 隐私风险 | 价值 |
|---|---|---|---|
| **甲：全屏** | 整屏截图 | 🔴 高 —— 可能截到密码框、聊天记录、银行界面 | 低（信息量过大，模型抓不住重点） |
| **乙：活动窗口** | 只截当前前台窗口 | 🟡 中 —— 仍可能截到私密内容 | 中 |
| **丙：用户框选区域** | 用户拖一个矩形，只截那块 | 🟢 低 —— 用户明确指定了"看这里" | **高**（最小必要原则） |

**已裁决：只做丙（框选）。**

理由（审计原文要点）：全屏与活动窗口在操作系统层面存在巨大的隐私穿透风险（密码框、银行界面、私人聊天随时可能入镜）；「让她自己抓屏」等于把隐私暴露的裁决权交给程序。只有用户主动点按、手动拉框，才是**明确、单次、知情**的授权，且局部框选的有效像素密度最高，模型识别最准。

#### 问题三：图送出去之后，留在哪？

| 选项 | 判定 |
|---|---|
| 只存在内存，用完即弃 | ✅ **唯一可接受** |
| 存到临时目录 | ❌ 会在磁盘留痕，且清理不保证 |
| 存进 `experiments.jsonl` / `experiences.jsonl` | ❌ **严重违规** —— 那是她"经历的档案"，截图像素不属于她的人格记忆，且不可撤回 |
| 存进研究导出 | ❌ 违反"不记像素内容"的审计口径 |

### 2.2 方案（已裁决为 B；A 为退化路径）

#### 方案 A：不做（退化路径）

- **条件**：目标 Provider 无 vision，或用户认为隐私风险不可接受。
- **收益**：零风险、零工时。
- **代价**：v1.8 只剩 v1.8-a（重逢心境），变成单功能版本 —— **可以接受，不为了凑规模而做**。

#### 方案 B：框选局部探针（**采用**）

**用户流程**：
1. 用户点「看看这个」按钮（主窗或对话窗）；
2. 主窗变半透明遮罩，用户拖一个矩形；
3. 松开 → 主进程 `capturePage(rect)` → 缩放 → data URL → 送模型；
4. 图**只进当轮尾部**（「【你看到了一块屏幕区域】+ 用户说：…」的客观描述），用完丢弃。

**技术前提（实测缺口）**：

| 缺口 | 现状 | 要做什么 |
|---|---|---|
| Provider `vision` 标记 | 全部 `false` | 注册表加写入路径（或按 connection 配置项） |
| 传输层 content parts | `openai-transport.js` 无 | 组装 `[{type:'text'},{type:'image_url',image_url:{url:'data:...'}}]` |
| 适配器 | 两个适配器无 `image_url` | OpenAI 兼容适配器加分支；**DeepSeek 原生适配器若无 vision 则明确报错**，不静默丢图 |
| 截图 API | 零命中 | `webContents.capturePage(rect)` |
| 遮罩 UI | 无 | 新建全屏透明遮罩（主窗内叠加或独立窗口） |

**审计口径**（照 v1.6 失败留痕体例）：
```js
auditVisionCapture({ rectW, rectH, bytes, elapsedMs, ok, errorType });
// 绝不记：像素、OCR 文本、窗口标题、URL
```

### 2.3 若实施 B：分步施工（6 步）

| 步 | 内容 | 可独立验收 |
|---|---|---|
| 1 | Provider `vision` 真实可用性验证（一次真实 API 调用） | 通过 / 不通过 |
| 2 | 注册表 `vision` 标记 + 能力不足时**显式报错** | 无 vision 时清晰失败，不静默 |
| 3 | 传输层 content parts 组装（纯函数，可单测） | 组装结果结构断言 |
| 4 | 主进程截图 + 缩放 + data URL（**不落盘**） | 内存断言 + 临时目录空断言 |
| 5 | 框选遮罩 UI + 二次确认 | 取消时不截 |
| 6 | 当轮尾部注入 + 审计留痕 | 历史 grep 不到；审计无像素 |

### 2.4 铁律（若做）

1. **只在用户显式唤起时截，绝不后台定时截屏。** 门禁：静态扫描，无 `setInterval` + `capturePage` 同现。
2. **图不落盘、不进历史、不进经历、不进导出。**
3. **默认关闭**，首次使用二次确认。
4. **审计只记尺寸/耗时/成败，不记像素与 OCR。**
5. **无 vision 能力时显式失败**，绝不静默丢弃图片后假装"她看过了"。
6. **不碰前缀缓存**：图只进当轮尾部，system 与 history 一个字节不动。

### 2.5 已裁决（2026-10-19 审计，四项全部落定）

|---|---|---|
| 1 | 目标 Provider 支持 vision 吗？ | **DeepSeek 官方 V3/R1 为纯文本，不支持。** 必须能力前置探测 + 置灰 |
