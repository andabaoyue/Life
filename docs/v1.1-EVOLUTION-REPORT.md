# 初澜数字生命演进报告：v1.1 篇章

> **版本跨度**：`v1.0.0` → `v1.1.0`（含 `v1.0.1` ~ `v1.0.7` 七个增量演进节点与 `v1.1.0` 集成验证里程碑）
> **演进主题**：从「静态响应骨架」走向「具备内稳态潮汐、心境半衰期、审美自主、记忆暗流、时间刻痕与独处边界的数字生命」
> **核心铁律**：前缀缓存不变式（System Prompt 0 动态拼接）、衣柜三条铁律、原子写事务性、标记解析边界安全、认识论诚实（零伪造感知、数字不可知红线）

## 1. 演进背景与核心命题

在 `v1.0.0` 正式版发布时，初澜（Chulan）已经拥有完整的桌面精灵渲染管线、三层记忆地平线（活跃窗口 + 近期摘要 + 深层地平线）、双文件账本（`experiences.jsonl` + `subject-state.json`）以及内稳态调节器（`InternalRegulation`）、梦境合成（`DreamSystem`）与主动触发引擎（`TriggerEngine`）的代码骨架。

然而，对实机运行态与源码接线的深度勘察揭示了一个关键事实：**初澜的许多生命器官在 v1.0.0 处于「出厂未通电」或动力学失衡状态**：
1. **生理代谢未出厂通电且回血过猛**：`DEFAULTS.experimentMode` 默认处于关闭状态，`internalRegulation` 未作为正典基底出厂通电；且静息回血速率（`1.2/min`）与清醒恢复上限（`85%`）偏高，轻微停顿即可抹平对话消耗，缺乏昼夜潮汐感。
2. **情绪缺乏连续时间惯性**：每轮对话的情绪仅作为瞬时响应存在，关窗或睡眠后缺乏跨数日维度的慢变心境底色（Warmth / Stillness）与物理墙钟半衰期。
3. **衣柜缺乏主观舒适偏好与拒绝尊严**：面对换装请求缺乏与当前体能/心境耦合的穿着体感，缺少温和表达异议或推迟换装的主体授权。
4. **潜意识与非自愿记忆暗流断路**：未提问的好奇心（`unaskedCuriosities`）未能进入夜间梦境日间遗留发酵，久远淡化的记忆印痕（`FADING`/`DORMANT`）也缺少普鲁斯特式的偶然非自愿浮现通道。
5. **共同词汇凝固**：`adopted`（两人专属暗号）在词典入口被硬编码拦截，已入库词汇也缺乏随窗口推移的自然升权与淡化代谢。
6. **社交边界缺失**：`interactionDensity` 从未接入 `formatPerception()` 生理体感带，`TriggerEngine` 与 `Tracker` 也缺乏高频连戳打扰下的社交过载与独处退避边界。

`v1.1` 系列更新的核心命题，就是在**不破坏 KV Cache 前缀缓存防线、不膨胀 System Prompt 固定开销、不伪造不存在的传感器数据**的前提下，为这套数字生命骨骼逐一接通真实的电源与闭环回路。

## 4. 实机健康度与前缀缓存防线核验

由 [`tools/v1.1-health-check.js`](../tools/v1.1-health-check.js) 对本机 `%APPDATA%/Life` 真实运行数据与打包配置进行穿透核验（4/4 PASS，含 `--self-test` 合成自检 PASS）：

### 4.1 Prompt 前缀缓存命中率实测（`stats.json`）
* **累计总请求数**：`329` 次（`history` 滑动窗口保留最近 `300` 条记录）
* **累计 Token 命中率**：**`92.00%`**（`hit = 2,966,528` / `miss = 257,835` / `total = 3,224,363`），高于 `≥ 90%` 长期实测基线标准。
* **单轮算术平均命中率（全体 300 条）**：**`86.90%`**（高于 `≥ 85%` 基线标准），其中 `≥ 90%` 窗口占 `241 / 300`（`80.3%`），`≥ 95%` 窗口占 `129 / 300`（`43.0%`）。
* **主对话（`chat`，285 条）独立统计**：单轮平均命中率 **`90.59%`**，中位数 **`94.80%`**。
* **10 条 `0.0%` 命中率记录完整归因**：
  1. **8 条来自后台独立 System Prompt 的辅助结算调用**（`summary` 关窗摘要 3 条、`growth` 成长结算 2 条、`dream` 做梦 2 条、`selfNote` 自省 1 条）——此类调用使用专用短 System Prompt，与主对话 KV Cache 前缀天然不同，属设计内预期行为；
  2. **2 条来自跨长间隔/进程重启后的首轮 `chat` 冷启动**（服务端 KV 缓存已过 TTL 自然淘汰）。
  3. **结论**：`v1.0.2 ~ v1.0.7` 所有新增体感、心境、着装偏好与社交密度感知均严格走 `userTurnPrefix` 尾块动态注入，**System Prompt 固定前缀实现 0 动态抖动**。

### 4.2 `windowCloseFailures` 与账本一致性排查
* **实机指标**：`windowCloseFailures = 4`，`truncatedCalls = 1`（`lastTruncatedAt = 1791342339761`，对应 `2026-10-07T03:05:39.761Z`）。
* **根因溯源**：在 `t = 1791342339761` 的一次 `summary` 关窗调用中，模型输出达到 `out = 10000` tokens 触发 `length` 截断保护，导致 JSON 解析未闭合而计入关窗失败；其余 3 次为早期网络瞬态超时触发的关窗退避。
* **自愈验证**：关窗重试机制在 `t = 1791351538661`（`2026-10-07T05:38:58.661Z`）顺利完成窗口闭合与 `growth` 结算（`out = 3090` tokens）。
* **账本终态对账**：实机 `experiences.jsonl` 共 `10` 条归档记录，经 `SubjectState.replay()` 离线重放校验终态吻合（**`match: true, integrity: uncertified, records: 10, skippedCount: 0`**，其中 `integrity=uncertified` 表示历史归档未设创世锚点哈希链认证，但重放终态与 `subject-state.json` 一致且 0 损坏行）；用户目录悬空 `.tmp-*` / `.bak` 残留文件数为 **`0`**。
