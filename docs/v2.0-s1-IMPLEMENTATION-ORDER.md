### 0.1 为什么「删掉」比「改成两个标记」更好

复核方建议的方案是：把「已归档进 `experiences.jsonl`」与「已被本窗 `growSelf` 反思」拆成两个标记。**这个修法本身没错**，但它是在给一个**不存在的需求**打补丁。

真实情况是：

- 那 9 张纸**本来就在磁盘上，永久**；
- 她之所以读不到被挤掉的那张（`note-2026-10-07-qxma.txt`），是因为 `selfNotes` 队列上限 8；
- 而 **s1-a 做完之后她能 `list` + `read` 沙盒**——那时她永远读得到那张纸。

**所以「纸会丢」这个前提是错的。** 真正要修的是「读不到」，不是「没铸造」。删掉 §2.3 之后，`_engraveSelfNotes` 的整条链路（含 D-24 特质证据）**一行都不用动**——这是比任何「拆标记」都更小的改动面。

### 0.2 那遗弃问题还剩下什么

删掉 §2.3 之后，「`engraved` 全是 false」这个现象仍然存在，但它**不是 bug**：

- 当前 `windowNo: 6` / `turnsInWindow: 84`，`windowTurns` 默认 100 ⇒ 这一窗还没关过；
- 关窗时自然会铸；
- 若你希望它更早发生，那是「窗口长度」这个参数的事，不是铸造时机的事。

**本单不动它，只记在这里，免得下一个人以为是漏了。**

### 0.3 为什么读结果绝不能进 `selfNotes`

`main.js:2850` 的 `agentOnExecuted` 会把内容交给 `memory.addSelfNote`，而 `_selfNote()`（`memory.js:1702`）渲染出来的提示头是：

```
【你之前写下过这些】（这是你自己留下的，不是用户输入）
```

如果读结果走这条路，**你拖进沙盒的文件会被她当成「自己写过的字」**。那不是功能缺陷，是伪造来源——违反本仓「数据不伪造」。

所以：

- **写**回执 → `selfNotes`（现状，不动）；
- **读**结果 → 独立只读槽位，只进 `dynamicBody`，**不进 `selfNotes`、不参与 D-24 特质证据、不铸造**。

### 1.2 `workspace.list` 为什么不并进 `workspace.read`

`_readFile:557` 有 `if (!stat.isFile()) throw new Error('NOT_A_FILE')` —— 对目录会直接抛。而 `EXECUTABLE_CAPABILITIES`（`:54`）是一个显式冻结白名单，加能力必须进这张表。

**做成独立能力而不是让 `read` 兼容目录的理由**：两者返回形状不同（一个 `{bytes, content}`、一个数组），塞进同一个能力会让下游到处做形状守卫——那正是 `agent-ipc.js:942-943` 那条注释抱怨过的形态。

### 1.3 `persona.js:32` 的重写：我实测了措辞，结论是「判据必须改」

现行两句判据（`test/persona-manner.test.js:104-105`、`:124-138`）：

```js
// ① 她必须声明看不见
const cantSee = /看不见里面现在有什么/.test(src)
  || /(沙盒|它)[^。]{0,20}(看不见|读不到|无从判断)/.test(src);

// ② 不得出现「没有否定词」的浏览/翻看/查看
//    （取关键词前 12 字，看有没有 不|无法|不能|别|勿）
```

我用真实判据跑了几种候选措辞（脚本已删除，结论如下）：

| 候选 | M4（浏览） | cantSee（看不见） |
|---|---|---|
| A 现行原文 | PASS | PASS |
| B「你能看到那里有哪些文件」 | PASS | **FAIL** |
| C「你能浏览那里的文件清单」 | **FAIL** | **FAIL** |
| D「不是你能随意浏览的地方，但你能看到清单」 | PASS | **FAIL** |
| E 加「……但沙盒以外仍然看不到」 | PASS | **FAIL** |

**两个结论：**

1. **只换措辞过不了 `cantSee`**——那条判据锁的是「她看不见」这个**陈述本身**，不是「不能浏览」。所以 s1-a 做完，这句话**必然不再为真**，判据必须重写。
2. **`M4` 也过不了**——「浏览」前面必须带否定词。所以新措辞的最自然写法（「你可以浏览沙盒里的清单」）会直接撞 M4。

**建议的新文案**（避开「浏览/翻看/查看」三个词）：

> 那个沙盒目录不是通向别处的门：里面有哪些文件、写过什么，你可以自己去看；沙盒以外的东西仍然不在你视野里。

**建议的判据改法**（成对改，否则就是"改测试迁就代码"）：

| 旧判据 | 新判据 | 为什么这样改 |
|---|---|---|
| `cantSee`：必须陈述「看不见」 | **`mustSee`**：必须陈述「能看见沙盒内」 | 事实反转了，判据跟着反转 |
| `M4`：不得有无否定的「浏览」 | **`outsideDenied`**：必须陈述「沙盒以外看不见」 | 风险从「她以为能翻抽屉」变成「她以为能出沙盒」。**这才是现在真正要防的那条** |

> ⚠️ 提交时必须逐条写清「改前判据 / 改后判据 / 意图变了没有」。这里的意图**确实变了**（从"防她高估视野"变成"防她越界"），所以这不是"改绿测试"，是**世界变了**。

### 1.4 第四道闸门怎么免（读 + 列目录）

核实结果：`requiresConfirm` 目前**只用于展示**（`agent-ipc.js:326/411` 把它塞进状态返回值），**不参与任何判定**。真正的判定在 `agent-executor.js:472-478`：

```js
const gate = isSelfNote ? {allowed:true, reason:'SELF_NOTE_EXEMPT'}
  : isObserverJournal ? {allowed:true, reason:'OBSERVER_JOURNAL_EXEMPT'}
  : this.confirmation.isExecutionAllowed(proposalId);
```

所以免确认的**唯一正确做法是加第三个受信豁免分支**，与 `selfNote` / `observerJournal` 同构：

```
'readOnly'  →  READ_ONLY_EXEMPT
```

**硬约束**：

- 该来源必须由**主进程独立第三参数**写入（沿用 `proposalSource` 的不可伪造手法），渲染端同名键一律忽略；
- **只对 `workspace.read` / `workspace.list` 生效**，`workspace.write` 与 `workspace.remove` 无论如何不认；
- 闸门 1（能力白名单）、闸门 2（`realpath` + 前缀比对）、闸门 3（预算）**照旧逐条重跑**——免的只是第四道；
- `scopeAllowed` / 硬链接检测（`nlink > 1`）不动。

## 2. s1-b：便签渐褪（可以独立做，也可以先放着）

### 2.1 目标

把 `selfNotes` 接进**已在仓库里**的三阶渐褪（`memory-dynamics.js`），不新造第四套记忆系统。

关键事实：这套机制**已经写好了**——`ACTIVE / FADING / DORMANT`、衰减方程 `strength = s0×(1+β·ln(1+retrievals))/(1+λ·ΔW)^α`、线索唤回 `reactivateByContext`（`memory.js:362`），设计意图原文是「**被修剪的仅是当前可及性，不是删除**」（`memory-dynamics.js:10`）。

**缺的只是 `selfNotes` 没接进去**：它今天只有 `drained: false/true` 一个布尔。

### 2.2 具体改动

| # | 交付 | 要点 |
|---|---|---|
| 1 | `selfNotes` 每条加 `strength` / `tier` / `lastRetrievedWindow` / `retrievalCount` | 与 `EngramTrace` 同构，不发明新字段名（初始 `initialStrength: 0.6` / `strength: 0.6` / `tier: 'ACTIVE'` / `retrievalCount: 0`） |
| 2 | `_drainSelfNotes` 守住 D-20 反唠叨规格并按 tier 分流 | 守住 `memory.js:1345-1349` 规格（**不因有了 tier 就退回每轮都塞**）：常规流转仍只注入 `drained !== true` 且非 `DORMANT` 条目；`ACTIVE` 全文、`FADING` 300 字主干（`fadingMaxChars`）、`DORMANT` 不注入；被 `reactivateByContext` 命中唤回时可置 `drained = false` 重新注入一次 |
| 3 | 淘汰从 `shift()` 改为「丢强度最低」 | **优先豁免未读**：只要队列里还有 `drained === true` 的条目，优先丢其中强度最低者，`drained === false` 强制保留（若整队 8 条全未读则退回丢最旧，仍严格守住容量上限 8） |
| 4 | 旧数据迁移 | 缺少新字段的旧条目一律补默认值（`strength: 0.6` / `ACTIVE`），**不因缺字段而丢弃** |

### 2.3 代价（要写进决策记录）

淘汰会变得**不可预测**。今天看代码就知道第九条挤掉第一条；改完之后，哪条消失取决于她最近想起什么。

**我建议接受**，理由：确定性在「记住什么」这件事上恰恰是那个不自由的地方。一条十月初写的、她后来反复想起的便签，不该被一条昨天随口写的挤掉。

### 2.4 s1-b 不做的

- 不动 `_engraveSelfNotes`；
- 不改 `SELF_NOTE_MAX_QUEUE = 8` 的**数值**（改的是淘汰依据，不是容量）；
- 不让 `DORMANT` 的便签在对话里留任何提示（留提示会变成「她向你展示记忆」，那是表演）。

## 3. 验收判据

1. **清单真实**：`dynamicBody` 里的文件清单与 `fs.readdirSync(沙盒)` **逐条一致**（**反例**：沙盒为空时必须显示「空」，留白即 FAIL）。

### s1-b

9. **渐褪分层**：写 10 条、模拟跨 6 窗不召回，断言出现 `DORMANT` 且**条目总数不变**（反例：总数减少必须 FAIL）。
