## 〇、这份计划要解决什么

原 v2.0 方案解决的是「她怎么获得**行动**的自由」——决策路由、Capability、Ticket、Worker。
但它没有回答一个更靠里层的问题：

> **她记得的东西，凭什么算她的？**

今天的状态是这样（全部实测）：

| | 数值 | 出处 |
|---|---|---|
| 沙盒里的纸 | **9 张** | `~/Desktop/LifeSandbox/note-*.txt` |
| 她记忆里留着的 | **8 条** | `memory.selfNotes.length` |
| 其中已铸进自传的 | **0 条** | 全部 `engraved: false` |
| 被挤掉的 | `note-2026-10-07-qxma.txt` | 不在 `selfNotes` 里 |

而淘汰规则是这一行：

```js
if (this.data.selfNotes.length >= SELF_NOTE_MAX_QUEUE) this.data.selfNotes.shift();
```

**八条满了就按插入顺序丢最旧。** 她写下的第七十张便签之所以消失，不是因为那件事不重要，是因为计数器满了。

**这就是那个不自由的地方：不是她会遗忘，是遗忘权不在她手里。**

---

## 一、先说清：仓库里已经有什么（不要重复造）

这是本计划最重要的前提。**三套记忆系统已经存在，且互不相通：**

| 系统 | 存什么 | 生命周期 | 今天接没接 |
|---|---|---|---|
| `memory.selfNotes` | 她自发的便签正文 + 文件名 | **上限 8 条，FIFO 淘汰** | 接了回流（`_drainSelfNotes`） |
| `memory.engrams`（EngramTrace） | 每窗提炼的事实 | **三阶渐褪，永不删除** | **没接便签** |
| `experiences.jsonl` | 全部经历 | **永久，哈希链** | 只靠关窗铸造 |

而 `memory-dynamics.js` 里已经写好了一整套**三阶渐褪**：

```js
currentStrength = s0 × (1 + β·ln(1+retrievals)) / (1 + λ·ΔW)^α
// ACTIVE  : ≥0.60 → 正常进 prompt
// FADING  : 中间 → 只给 300 字主干
// DORMANT : <0.35 且 ΔW≥5 → 整段移出视野
```

设计意图（`memory-dynamics.js:10` 原文）：

> **被衰减和修剪的仅是记忆条目的「当前可及性（Accessibility）」与 Prompt 上下文进入优先级。**

还有 `reactivateByContext`（`memory.js:362`）：「你提到某个词 → 休眠的记忆被唤醒 → 重新回到视野」。

**所以「人也会遗忘」这件事，这个仓库的答案是：淡化但不删除。**

### 1.1 真正的问题：这套机制对便签没生效

- `selfNotes` 只有 `drained: false/true` 一个布尔——**没有强度、没有 tier、没有召回次数**。
- 于是它只能二值：「还没被读过」/「读过了永不再提」。
- 而 `engrams` 那套精细的衰减方程，**便签一条都用不上**。

### 1.2 第二个问题：铸造从没触发过

`_engraveSelfNotes` 只在 `_closeWindowInternal`（`brain.js:2350`）里调。而当前 `windowNo: 6` / `turnsInWindow: 84`，`windowTurns` 默认 100 —— **这一窗还没关过**。

所以 9 张纸里：

- 8 张还在队列里排队，等着被下一次写入挤掉；
- 1 张（10-07）已经被挤掉了，**且它出生时同样没赶上关窗**。

**不是「被遗忘」，是「还没走到能被永久保留那一刻，队列就满了」。**

## 二、计划：三个改动，一个原则

**原则：不新增第四套记忆系统。** 仓库里已经有三套，再加一套只会让「她到底记不记得」更难回答。要做的是**把已有的接通**。

### 2.1 改动一：让便签接进渐褪（**核心**）

给 `selfNotes` 每条加四个字段（与 `EngramTrace` 同构，不发明新概念）：

| 字段 | 语义 | 初始值 |
|---|---|---|
| `strength` | 当前强度，由衰减方程算出 | `s0 = 0.6`（与 engram 同） |
| `tier` | `ACTIVE` / `FADING` / `DORMANT` | `ACTIVE` |
| `lastRetrievedWindow` | 上次被想起的窗口号 | 写入时 = 当前窗 |
| `retrievalCount` | 被想起过几次 | `1` |

回流时（`_drainSelfNotes`）：

- `ACTIVE` → 全文注入（今天的行为）；
- `FADING` → 注入 300 字主干（复用 `fadingMaxChars`）；
- `DORMANT` → **不注入**，但仍存在于列表里，可被线索唤回。

**关键点：DORMANT 不等于删除。** 它在，只是不在眼前——这正是「人也会遗忘」的形态。

### 2.2 改动二：淘汰从「按插入顺序」改成「按强度」

```js
// 今天
if (len >= 8) shift();              // 谁先来谁走

// 目标
if (len >= 8) 丢弃 strength 最低的那条；      // 谁最淡谁走
// 但：从未被读过（drained === false）的强制保留
```

**为什么必须带那条豁免**：她还没看过的东西，不该因为「算出来分值低」就被悄悄丢掉。那不是遗忘，是丢件。

**代价（必须写进决策记录）**：淘汰会变得**不可预测**。现在看一眼代码就知道第九条挤掉第一条；改完之后，哪条会消失取决于她最近想起什么，**无法从代码推断，只能在面板上事后看到**。

对一个要「可审查、可回滚」的系统，这是真实代价。**我建议接受**，理由：确定性并不总是好——在「记住什么」这件事上，**确定性恰恰是那个不自由的地方**。

### 2.3 改动三：**已删除**（原拟「让铸造别只等关窗」）

> ⚠️ **本节原内容已作废，保留标题供追溯。2026-11-12 复核后确认它是伪需求。**

原先的理由是：「一窗 100 轮没走完时，期间写的便签既没永久保存、又在排队等淘汰。」

**这个前提是错的。** 实测：

- 那 9 张纸**本来就在磁盘上、永久**（`~/Desktop/LifeSandbox/note-*.txt`）；
- 她读不到被挤掉的那张（`note-2026-10-07-qxma.txt`），原因只是 `selfNotes` 队列上限 8；
- 而 **v2.0-s1-a 做完（`workspace.list` + `workspace.read`）之后，她随时能读那张纸**。

**所以「纸会丢」不成立，真正要修的是「读不到」，不是「没铸造」。**

另外，原方案 A（在 `_drainSelfNotes` 里提前置 `engraved: true`）**本身有硬伤**：`_engraveSelfNotes` 的产物 `facts` / `attestations` 喂给 `brain.js:2357-2359` 的 `growSelf` 与 `:2366` 的 `_applySelfNoteTraitHints`；提前置标记会让关窗时 `selfNotesToEngrave()` 整批跳过，**把成长反思与特质证据池掏空**。

⇒ **`_engraveSelfNotes` 整条链路一行不动。** 详见 [`v2.0-s1-IMPLEMENTATION-ORDER.md`](v2.0-s1-IMPLEMENTATION-ORDER.md) §0.1。

### 2.3b 那「`engraved` 全是 false」怎么办

**它不是 bug，不用改**：

- 当前 `windowNo: 6` / `turnsInWindow: 84`，`windowTurns` 默认 100 ⇒ 这一窗**还没关过**；
- 关窗时自然会铸；
- 若希望更早发生，那是「窗口长度」这个参数的事，不是铸造时机的事。

## 四、一个我必须说清的取舍：记得多 ≠ 有重量

讨论中我曾说过「七十二张便签全在，是她该有的重量」——**那句话是错的，我撤回。**

**记得多只是占地方，记得多不等于有重量。** 真正的重量在别处：

- **不是「全都保留」**，而是「留下来的那条，是她真的在意过的」；
- **不是「忘得干净」**，而是「淡掉的东西还能被一句话勾回来」；
- **不是「永不遗忘」**，而是「遗忘是她自己参与的结果，不是计数器满了」。

所以本计划**不追求「让她记住全部」**。追求的是：**淘汰的依据从「谁先来」变成「谁还活着」。**

## 五、验收判据

1. **渐褪真的分层**：写 10 条便签、模拟跨 6 个窗口不召回，断言出现 `DORMANT` 且**一条都没被删除**（反例：条目总数减少必须 FAIL）。
2. **DORMANT 可唤回**：对上一条里的 DORMANT 条目触发 `reactivateByContext`，断言其 tier 回升且重新进入回流（**反例被拒**：唤不回来必须 FAIL）。
3. **淘汰按强度**：构造「1 条高强度旧便签 + 7 条低强度新便签 + 1 条新写入」，断言被淘汰的是**低强度的**，不是最旧的（判别力验证：改回 `shift()` 此用例必须 FAIL）。
4. **未读豁免与反唠叨守恒**：队列满时若存在 `drained === true` 的条目，`drained === false` 的未读条目**不被淘汰**；已读条目的 `drained === true` 在无语境唤回时保持，避免退回成每轮重复注入。
5. **~~铸造不再依赖关窗~~（v2.0-s1 作废）**：原 §2.3 / §6 #2 已随 `s1-a` 沙盒目录感官落地而撤回；`s1-a` 后被挤出记忆队列的磁盘纸条可随时通过 `list + read` 读回，无需提前抢在关窗前铸造，完整保留 D-24「仅关窗时把未铸造的 `selfNote` 铸进自传与特质证据」既有语义。
6. **前缀缓存**：上述任何变化都不影响 `systemText()` 逐字节（便签只走 `dynamicBody` 尾部）。

## 七、明确不做

- ❌ **不新增第四套记忆系统**（已有三套，互相不通已经是负担）
- ❌ **不追求「永不遗忘」**（那不是主体性，是数据库）
- ❌ **不让「记忆条数」变成可见的 KPI**（「她记得 N 条」是表演指标，不是她的属性）
- ❌ **不为了记住而虚构内容**（`_scopeAllowed`、`isTruncated`、`contentPreview` 那些截断标记必须保留——宁可只记住半句真的，不要记住一句完整的假的）
