## 2. 分步施工（共 3 步 + 1 步预留）

### 第 1 步：`CAPABILITY_META` 元数据升级 + 判定收口

**目标文件**：`src/agent-interfaces.js`、`src/agent-ipc.js`

1. **`CAPABILITY_META` 追加只读策略键**（`agent-interfaces.js:84-108`，仍整体 `Object.freeze`）：

   | 键 | 语义 | `workspace.read` | `workspace.write` | `process.execute` | `network.request` |
   |---|---|---|---|---|---|
   | `enforcesWriteExtension` | 建案前是否跑扩展名白名单 + Windows 畸形名检查 | `false` | `true` | `false` | `false` |
   | `requiresContentSnapshot` | 建案时是否强制绑定 SHA-256 权威正文快照 | `false` | `true` | `false` | `false` |
   | `checksOverwrite` | 待决卡片是否提示「将覆盖已有文件」 | `false` | `true` | `false` | `false` |

   > 🔴 **这三个键的语义方向与 `hardDenied` 相反**：`hardDenied: true` 是「更严」，而 `requiresContentSnapshot: false` 是「**不检查**」。所以判据必须是**加法式**，不能是替代式（见下条）。

2. **四处判定改为加法式**（既有行为当下限，元数据只做追加）：

   ```js
   // agent-ipc.js:215
   const writeMeta = CAPABILITY_META[capability] || null;
   if (capability === 'workspace.write' || (writeMeta && writeMeta.enforcesWriteExtension === true)) {
     // …原扩展名 / 畸形名检查一字不动
   }
   ```

   `:378`（`checksOverwrite`）、`:473`（`requiresContentSnapshot`）、`:743`（`requiresContentSnapshot`）同款改法。

   > **为什么必须是 `A || meta.B` 而不是 `meta.B`**：后者在 `register()` 新增能力时读到 `undefined` ⇒ 跳过检查 ⇒ 新增一条能绕过 SEC-01 的快照绑定的路。本仓纪律是「加防护要数受保护入口数」，这里是同一个道理：**新写法保护的入口集合必须 ⊇ 旧写法**。

3. **`CAPABILITY_META` 必须在模块内直接可见**：若 `agent-ipc.js` 当前只解构了 `CapabilityRegistry`，需从 `agent-interfaces.js` 追加导出 `CAPABILITY_META`（只读引用，`Object.freeze` 已在定义处）。

4. **4 处注释同步校准**（`:29, :226, :334, :468`）：保留原决策背景，末尾补一句「该判定现已由 `CAPABILITY_META` 的 `enforcesWriteExtension / requiresContentSnapshot` 追加驱动，字面量分支仍是下限」。**不得删除原注释**。

5. **`:291` 与 `:484/:495/:506` 保留，各补一句注释**说明为何不元数据化（展示口径 / 未校验输入不入审计）。

### 第 2 步：新增 `src/agent-router.js` —— 统一决策**入口**

**职责定位**：只做三件事——**单一消费**、**统一分派**、**统一记账**。**不搬函数体、不重写拟稿逻辑、不自己调 LLM。**

1. **对外只暴露一个入口**：

   ```js
   agentRouter.handleEvent({ kind, trigger, windowCloseRes }, deps)
   // kind ∈ 'turn_chat' | 'proactive_idle' | 'window_closed'
   ```

2. **单一消费（本步的核心收益）**：
   - `turn_chat` 进入同步段后立刻：`const intent = brain._pendingAgentIntent; brain._pendingAgentIntent = null;`
   - 之后把 `intent` 作为**显式参数**传给下游，**不再由 `maybeAskForSelfNote` 回落读 `brain._pendingAgentIntent`**（删掉 `main.js:409` 的 `|| (brain && brain._pendingAgentIntent)` 回落分支）。
   - ⇒ 全仓 `_pendingAgentIntent` 的读取点从 2 处收敛为 **1 处**，`main.js:1285-1297` 靠「恰好没 `kind`」的巧合安全从结构上消失。

3. **统一分派顺序**（与现行执行顺序逐条对齐，不得重排）：
   | 事件 | 现行顺序 | Router 内顺序 |
   |---|---|---|
   | `turn_chat` | `tryBuildProposalFromIntent()`（`:1298`）→ `maybeAskForSelfNote(intent)`（`:1313`） | 同序，**两次调用都保留**（前者只处理写意图，后者只处理 `wantToLeaveSomething`，互斥但都在场） |
   | `proactive_idle` | `maybeAskForSelfNote(trigger.selfIntent)`（`:1312`） | 只调它 |
   | `window_closed` | `maybeAskForObserverJournal(res)`（`:1246`） | 只调它 |

   > ⚠️ `turn_chat` 必须**两个都调**：现在能靠「字段已被置空 + 没有 `kind`」让第二个自然空转；收敛成单点消费后，`maybeAskForSelfNote` 拿到的仍是同一个 `intent` 对象，它会因 `intent.kind !== 'wantToLeaveSomething'` 正常返回。**这条正是 `d27:696` 钉的判据，必须保住。**

4. **明确不搬的东西（与上一版的关键差异）**：
   - `if (mode === 'off') return;` **留在函数体内**（`agent-observe-mode.test.js:236-239` 按偏移钉着它必须在 `await brain.askForSelfNote` 之前）；
   - `markObserveEpoch` 记账**留在原处**（`main.js:437-442` / `:615-620`）。挪进 Router 会改变它与 `main.js:583-590` 配额探针的先后，等于让「预算已耗尽」也记一次进入观察期；
   - `observe` 分流与 `noteObserved` **留在原处**（`:486-489` 钉着 `noteObserved(` 在函数体内）；
   - 文件名校验三判据（`path.isAbsolute` / 分隔符 / 连续点）**留在原处**（`d10:145-155` 钉着）。

5. **Router 内可选的第一层快筛（只做无副作用的）**：
   - `deps.agentSandbox` 是否存在、`sandboxUnavailable` 是否为真 → 直接短路，不调任何拟稿函数；
   - **不查预算、不查档位、不记账**（那三件留在原处，理由见上）。
