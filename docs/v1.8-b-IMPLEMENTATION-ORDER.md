## 2. 分步施工（6 步）

### 第 1 步：vision 能力标记（改掉过期标记）

**`src/provider-registry.js`**：

```js
// deepseek 注册项
capabilities: { streaming: true, usage: true, systemMessage: true,
                vision: true, tools: false, jsonMode: false }
```

**但不能一概而论**：`deepseek-v4-pro` 不支持。所以需要**按模型名判定**：

```js
/**
 * 该模型是否支持图片输入。
 * 依据官方文档：deepseek-flash 支持（JPEG/PNG/GIF/WebP），deepseek-v4-pro 不支持。
 * @param {string} modelId
 * @returns {boolean}
 */
function modelSupportsVision(modelId) {
  const m = String(modelId || '').toLowerCase();
  // v4-pro 明确不支持；flash 系列支持
  if (m.includes('v4-pro') || m.includes('v3') || m.includes('r1')) return false;
  return m.includes('flash');
}
```

> ⚠️ **宁可保守**：无法识别的模型名一律返回 `false`。**宁可少看图，不可假装看过。**

### 第 2 步：传输层支持 content 数组

**当前**：`openai-transport` 收到的是 `[{ role, content: 'string' }]`，原样序列化。

**改造点**：需要一个「追加图片到指定消息」的能力。**最小侵入做法**：

不改 transport，而是在 `brain.js` 构造 messages 之后、调 `api.stream` 之前，**就地替换最后一条 user 的 content**：

```js
/**
 * 把图片附加到本轮 user 消息（只影响本次请求，不影响 history）。
 * @param {Array} messages memory.build() 的产出
 * @param {string} dataUrl 形如 data:image/png;base64,xxx
 * @returns {Array} 新的 messages（不改原数组）
 */
function attachImageToLastUser(messages, dataUrl) {
  const out = messages.slice();
  for (let i = out.length - 1; i >= 0; i--) {
    if (out[i] && out[i].role === 'user') {
      const text = String(out[i].content || '');
      out[i] = {
        role: 'user',
        content: [
          { type: 'text', text },
          { type: 'image_url', image_url: { url: dataUrl } }
        ]
      };
      break;
    }
  }
  return out;
}
```

🔴 **必须验证**：adapter 是否原样透传 content 数组（不做 `String(content)` 之类的转换）。

### 第 3 步：截图（主进程，内存中）

```js
ipcGuard.handle('vision:capture', async (e, opts = {}) => {
  // 入参只有矩形，不接受任意路径/URL
  const rect = normalizeRect(opts.rect);   // { x, y, width, height }，全整数
  if (!rect) return { ok: false, errorType: 'bad_rect' };

  // 🔴 只截**主显示器**的工作区，且限制最小尺寸（防误触 1×1）
  if (rect.width < 16 || rect.height < 16) return { ok: false, errorType: 'rect_too_small' };

  const img = await win.webContents.capturePage(rect);
  if (!img || img.isEmpty()) return { ok: false, errorType: 'capture_failed' };

  // 缩放到短边 ≤ 1024（控 token 成本）
  const resized = img.resize({ width: /* 等比 */ });
  const dataUrl = 'data:image/png;base64,' + resized.toPNG().toString('base64');

  // 🔴 只存在内存，随返回值送给渲染层后即弃；本函数不写任何文件
  return { ok: true, dataUrl, width, height, bytes };
});
```

**边界**：
- 入参**不接受**任意文件路径 / URL（防 SSRF 与任意读文件）；
- 截图后**立刻**转 data URL，`nativeImage` 对象不缓存；
- **绝不调用** `fs.writeFile`。

### 第 4 步：框选 UI

**方案**：复用主窗，临时切到"框选模式"。

- 用户点「看看这个」→ 主窗进入框选态：加半透明遮罩、`-webkit-app-region: no-drag`、光标变十字；
- 用户拖出矩形 → 松开 → 调 `vision:capture`；
- ESC / 右键 → 取消，不截。

> ⚠️ **主窗是透明无边框窗口**，遮罩要用 `body.vision-picking::after` 画，不能新建窗口（新建全屏窗口会闪一下，体验差且需要额外权限）。

### 第 5 步：注入当轮尾部

照 `_bedsideNote` / `_reunionNote` 的挂点：

```js
const visionNote = this._visionNote();   // `【你看到了一块 ${w}×${h} 的屏幕区域】`
```

**顺序**：`bedside → selfNote → reunion → vision → suffix`

🔴 **图不进 history**：图片只附加到**本次请求的 messages 副本**，`memory.history` 里只有一行文字说明。

### 7.1 四处与本文上文的直接冲突

| 上文写的（施工前方案） | 实际落地 | 为什么改 |
|---|---|---|
| 第 4 步：“复用主窗，临时切框选模式” | **独立全屏窗口** `vision-picker.html/js` + `src/vision-picker-window.js` | 主窗只有 256×320，`position:fixed;inset:0` 只能盖住这个小窗，**根本框不到屏幕其他区域**；“看屏幕”名不副实 |

### 7.3 返工中暴露、原方案完全没提的坑

1. **`destroy()` 会卡死进程** —— `setImmediate` 与 `setTimeout(0)` 延后销毁**实测都还是卡**。定案只 `hide` + `hiddenPicker` 复用（代价：隐藏窗常驻几十 MB，比“用户屏幕被占死”可接受）。
2. **“blur 自动关”实测否决** —— 拖框瞬间会短暂触发 blur，会在拖到一半时把遮罩关掉。
3. **打包白名单四处** —— `vision-picker.html/js` 原本不在任何白名单：`electron-builder.yml` 的 `files`、`tools/asar-check.js` 的 `REQUIRED_FILES`、`tools/release-check.js` 的 `RUNTIME_ENTRIES`、`tools/public-export.js` 的 `INCLUDE`。**漏任何一处，打包后框选窗都打不开。**
4. **三层逃生门是必须的** —— 主进程 `before-input-event` 拦 ESC（不经过渲染层、不过 IPC 校验）+ 渲染层 `closePicker` IPC + `window.close()` 原生关闭。前两层全挂时第三层仍能脱困。
5. **通道级收窄，不能只加白名单** —— 把框选窗整体加进信任列表等于让一个加载在透明全屏窗里的页面继承主窗全部 IPC 能力，所以只放行 vision 那 4 条。

### 7.4 原文遗留、实际未按原文落实的两点（如实标注）

- **§2 铁律 4「默认关闭，首次使用二次确认」**：实际实现里**没有**独立的首次使用二次确认步骤 —— 授权语义改由“用户主动点菜单 + 亲手拖框”这一动作本身承担（每次截图都是一次明确的单次授权）。这与铁律的**意图**一致，但**形式上与原文不同**，故在此标明，不冒充“已按原文实现”。
- **§2 第 5 步“顺序：bedside → selfNote → reunion → vision → suffix”**：以 `src/memory.js` 实际代码为准，本节未逐字核对顺序，如需精确断言请以代码与 `test/v18-vision.test.js` 为准。
