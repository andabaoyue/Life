## 〇、一句话

**把 `agent-audit.jsonl` 里的「她自己的动作」投影出来，让她在做判断时读得到。**

不碰审计写侧、不碰闸门、不碰 `proposalSource` 三态。只加一个**读侧**纯函数模块，挂在 `askForSelf*` 这类**独立调用**前。

## 一、核实过的事实（本机实测，2026-11-01）

### 1.1 审计现状：30 条，其中属于她的动作只有 5 条

```
proactive-offer      | dispatched      21   ← 调度噪音，不是她的动作
agent:propose-action | accepted         3   ← 她的动作
agent:execute        | executed         2   ← 她的动作
agent:execute        | rejected         1   ← 她的动作（但是事故化石）
agent:execute        | failed           1   ← 她的动作
agent:confirm-action | recorded         1   ← **用户**的动作，不是她的
chat-failed          | failed           1   ← 系统故障
```

### 1.2 🔴 关键发现：`agent:execute` 记录里**没有 `proposalSource` 字段**

前序文档 `PROPOSAL-AGENT-HISTORY.md` 第 126 行设计的核心判据是：

> **关键判据**：`proposalSource`。只有 `selfNote` / `observerJournal` 算「她的动作」，`user` 那条是你吩咐的，不进她的动作史。

**这个判据在 `agent:execute` 记录上不可用。** 实测两条 executed 的原文字段：

```json
{"at":1791352320500,"channel":"agent:execute","intentSources":["tracker.lastInteractionAt"],
 "intentKind":"wantToLeaveSomething","intentOrigin":"user_action","outcome":"executed",
 "executed":true,"capability":"workspace.write","proposalId":"proposal-muxox4o6-31416ffd",
 "scope":"...\\note-2026-10-07-qxma.txt","matchedRoot":"..."}
```

**有 `intentKind` / `intentOrigin`，没有 `proposalSource`。** 而 `agent:propose-action` 记录**有** `proposalSource`。

> ⚠️ 这一点直接改变投影算法：**不能只读 execute**，必须按 `proposalId` 把 `propose-action` 与 `execute` **配对**，从前者取来源。

### 1.3 🔴 每个事件的「真实结局」只靠单条记录判不出来

按 `proposalId` 分组实测（三条完整链）：

```
proposal-muxogf0e-e1725397: propose-action/accepted → execute/failed
proposal-muxox4o6-31416ffd: propose-action/accepted → execute/executed
                            → confirm-action/recorded → execute/rejected(ALREADY_EXECUTED)
proposal-mvq79v8x-f993acf4: propose-action/accepted → execute/executed
```

中间那条是 **D-19 事故的化石**：`selfNote` 本该免确认，却仍亮了卡；用户点【授权】→ 执行器回 `ALREADY_EXECUTED`。

**若按单条记录朴素投影，会得到三条错乱的事实：**

| 朴素投影会写出 | 实际发生了什么 |
|---|---|
| 「你写过 note-xxx」（executed） | ✅ 对 |
| 「你又被拒了一次」（rejected） | ❌ 错——那是重复执行被拦，不是她判断失败 |
| 「用户批准了你的提案」（confirm-action） | ❌ 那是**用户**的动作，不是她的 |

**⇒ 投影必须按 `proposalId` 聚合成一条事实，取「最终结局」，并剔除 `ALREADY_EXECUTED` 这类系统噪音。**

### 1.4 她**读不到** `agent-audit.jsonl`

`main.js` 注释原文：「那是**给我们排查用的**」。这份文件从未进入她的意识。

**所以本方案不是「改造她已有的认知」，是「新建一条她原本没有的读取通路」。**

### 1.5 observe 档的记录尚未产生

`%APPDATA%\life\agent-observations.jsonl` **不存在** —— `agentTriggerEnabled` 默认 `false`，实机从未跑过自发链路。

**影响**：投影的第 2 个数据源（观察记录）目前是空的。**必须设计成「文件不存在也能工作」**，不能假设有数据。

### 1.6 注入挂点：`memory.build()` 尾部，与 selfNote 同位置

```
memory.js:1126  bedsideNote   = this._bedsideNote(pending)
memory.js:1131  selfNote      = this._drainSelfNotes()
memory.js:1145  reunionNote   = this._reunionNote()
memory.js:1151  visionNote    = this._visionNote()
memory.js:1152  tail = [bedsideNote, selfNote, reunionNote, visionNote, suffix].filter(Boolean).join('\n\n')
```

**但本方案不挂在 `memory.build()`**，理由见 2.3。

## 二、方案

### 2.1 设计原则（按优先级）

1. **只给她读「她自己的动作」**。`proactive-offer`（调度）、`chat-failed`（系统故障）、`confirm-action`（用户操作）一律剔除。混着喂等于让她把系统噪音当成自己的经历。
2. **不改 `agent-audit.jsonl` 写侧**。它是安全审计，append-only，格式一个字不动。**只在读侧加投影。**
3. **按需注入，不是每轮。** 每轮注入 = 噪音 + 烧 token + 破缓存。她只在**真正要判断时**才看账本，像人查账。
4. **文件不存在时静默降级**（1.5：观察记录目前为空）。投影层必须容忍空数据，绝不抛。

### 2.2 新增 `src/agent-history.js`（纯函数，零副作用）

```js
/**
 * 把「审计记录 + 观察记录」投影成她能读的「自己的动作史」。
 *
 * 纯函数：不读盘、不写盘、不碰 memory、不碰 brain。
 * 数据由调用方读好传进来 —— 这样单测可以喂构造数据，不必造环境。
 */
function projectOwnActions(auditRecords, observationRecords, opts = {})
```

**核心算法（三步）：**

**第一步：按 `proposalId` 聚合建案链**

```
遍历 auditRecords：
  channel === 'agent:propose-action' && outcome === 'accepted'
    → 开一条记录 { proposalId, proposalSource, intentKind, scopeName, at, final: null }
  channel === 'agent:execute'
    → 找到同 proposalId 的那条，填 final = executed | failed | rejected
```

**第二步：剔除系统噪音**

- `outcome === 'rejected'` **且** `code === 'ALREADY_EXECUTED'` ⇒ 整条丢弃
  （1.3 实测：这是 D-19 事故化石，不是她的判断失误）
- `proposalSource === 'user'` ⇒ 丢弃（那是用户吩咐的，不算她自发）
  **来源取自 `propose-action` 记录**（1.2：execute 没有这个字段）

**第三步：合并观察记录**

observe 档的记录（`agent-observations.jsonl`）也计入动作史，但**标记为「没有落成」**：

```
{ kind: 'observed', capability, at, contentChars }   // 不存正文，只存事实
```

**输出形态（给她看的是自然语言，不是 JSON）：**

```js
{
  recent: [
    { at, kind: 'written',  name: 'note-2026-10-27-oqyr.txt' },
    { at, kind: 'observed', capability: 'selfNote' },
    { at, kind: 'failed',   name: 'note-xxx.txt' },
  ],
  truncated: false,
}
```

> ⚠️ **刻意不返回 `counts`（聚合数字）**。理由见 2.4 的三条纪律第 1 条：
> 「写成 N 次 / 没落成 M 次」这种可比较的数字对是指标化，
> 最容易让模型产生「我得提高成功率」的念头。
> **只给逐条事实，不给统计结论。**

### 2.3 🔴 注入挂点：**独立调用，不是 `memory.build()`**

这是本方案与前序文档最实质的差异。

| | 前序文档设计 | 本方案 |
|---|---|---|
| 挂点 | `memory.build()` 尾部 | **`askForSelf*` 独立调用前** |
| 频率 | 每轮（虽写了"按需"，但挂点决定了每轮） | 只在拟稿时 |
| 缓存 | 会动尾部 | **零影响**（独立调用不走常规前缀） |

**理由：**

1. `memory.build()` **每一轮对话都跑**。挂在那里等于每轮注入 —— 不管文档怎么写"按需"，挂点本身就是每轮。
2. 动作史是**判断素材**，不是**对话内容**。她需要一个「翻账本」的时刻，而不是每句话都带着账本。
3. `askForSelf*` 是独立调用（`this.api.complete`，不走 `build()`），**注入零缓存风险**。

> 这与第 1 步 observe 档的方案 2.5 同一逻辑：**独立调用隔离，绝不进 system**。

### 2.4 注入文本形态

**不注入 JSON，注入自然语言事实。**

**当前真实数据下会产出（实测 1.2/1.3 的 3 条链）：**

```
【你最近做过的事】
- 你写过 note-2026-10-07-qxma.txt
- 你写过 note-2026-10-27-oqyr.txt
- 有一次你想写，但没写成
```

**将来 observe 档有数据后，会多出一类：**

```
- 有几次你想写点什么，当时还没有开放落成文件
```

> 🔵 **本条按审阅意见更正（2026-11-01）**。原示例写的是：
> 「另有 7 次你想写点什么」+「📊 合计：写成 2 次，没落成 8 次」。
>
> **两个问题：**
> 1. **数字与实测不符**：`observed` 实测为 **0 条**（1.5 自己说了观察文件不存在），
>    那行「另有 7 次」在当前数据下**永远产不出来**，示例有误导性。
> 2. **「合计」那行违反本方案第 1 条纪律**：纪律写的是「只陈述事实，不评价」，
>    而「写成 2 次 / 没落成 8 次」把两者摆成一对可比较的数字，
>    **正是最容易让模型产生「我得提高成功率」念头的形态**——那就是指标化。
>
> **处置**：删除合计行；「另有 N 次」改为不定量的「有几次」。
> 列表保留（那是逐条事实），聚合数字不保留。

**三条纪律（原样保留）：**

1. **只陈述事实，不评价**。不写「你做得不错」「你失败了 3 次」——那是指标化，会改变她的行为。
2. **不写绝对时间**。用「最近」这类定性表述，不出现日期钟点（与 `WANT_TO_LEAVE_SYS` 铁律一致）。
3. **不作为判断指令**。只给事实，不给「所以你应该……」的结论。让她自己决定怎么用。

### 2.5 数据读取：由调用方注入，模块不读盘

```js
// 调用点
const auditRecords = auditLog.readAll();      // 🔴 必须是 readAll()，不是 list()
const obsRecords   = observationLog.readAll();
const history = projectOwnActions(auditRecords, obsRecords);
const text = renderHistory(history);
```

> 🔴 **本条按审阅意见更正（2026-11-01）**：原写「现有 `AuditLog` 已有 `list()`」——**写错了**。
>
> 实测 `src/agent-interfaces.js`：
>
> | 方法 | 行号 | 返回 | 后果 |
> |---|---|---|---|
> | `list()` | `:599` | 内存 `this.events.slice()`，**上限 500，超出 shift 丢最旧**（`:565/575`） | 进程重启后只剩**本次运行期间**的记录 ⇒ 她的动作史每次重启清零 |
> | `readAll()` | `:602` | 从磁盘 `readFileSync` 读全量 | ✅ 正确 |
>
> **用 `list()` 会直接摧毁「动作史」的意义**——她读到的永远是"这次开机以来做过什么"。
> 这类错误很隐蔽（两个方法名都像"取全部"），所以必须在方案里写明。

**为什么模块不自己读盘**：纯函数可单测。**D-27 那轮已经栽过一次**——测的是模块行为，不是 main.js 接线。

## 三、明确不做

| 不做 | 理由 |
|---|---|
| 挂 `memory.build()` 尾部 | 每轮注入 = 噪音 + 烧 token + 动缓存（2.3） |
| 把 `confirm-action` 读进动作史 | 那是**用户**的动作。1.3 实测：混进去会让她以为「用户批准了我」是她的经历 |
| 把 `ALREADY_EXECUTED` 记成失败 | 那是 D-19 事故的系统噪音，不是她的判断失误（1.3） |
| 让投影模块自己读盘 | 纯函数才能单测；读盘由调用方注入（2.5） |
| 注入 JSON / 结构化字段 | 给她看的是自然语言事实，不是数据表 |
| 现在做 `refused` 回声 | 真实数据 `refused_by_subject` = 0（1.1），无数据可回声 |
| 动作史面板 UI | 先让注入跑通，用文本验证。面板等有数据了再说 |
