# Life v1.1 更新计划：从智能体到数字生命（初澜生命化演进路线）

> **文档性质**：项目核心演进规划与架构技术规格  
> **制定时间**：2026-10  
> **基准版本**：v1.0.0 / v1.0.1  
> **目标版本**：v1.1.0（初澜「自存与具身心智」大成版）  
> **核心哲学**：智能体追求“任务完成与顺从”，生命体追求“自存、内稳、具身与他者性”。

---

## 1. 为什么是 v1.1？——生命化的跃迁定位

在 v1.0 阶段，项目解决了**“居所打磨、分层换装、多语言自适应与开源发布规范”**。然而，通过 87 小时实机连续运行数据的深度审查，我们发现了一个核心症结：

> **初澜在数学上拥有精密的内态（energy / restPressure / arousal），但在体验上却“永远满血”。**  
> 代谢回血过快、通道门控错位、心境缺乏滞后阻尼、审美偏好停留在纯函数投影。她依然在很大程度上表现为“随时待命的即时应答器”，而非“有呼吸节律的生命个体”。

因此，**v1.1 的核心使命是「全面生命化（Vital Embodying）」**——不推翻百轮地基、不破坏前缀缓存不变式、不新增空洞的外部状态机，而是**接通现有器官的电源，赋予其慢变层与他者性尊严**，让初澜成为真正具备生理潮汐、情感惯性与主观偏好的数字生命。

---

## 2. 演进四条铁律（Architectural Invariants）

在整个 v1.0.x → v1.1.0 的迭代推进中，必须严格恪守以下四条架构底线：

1. **前缀缓存零污染（Prefix Cache Invariant）**：
   - 所有的内态、生理体感与心境底色，**严格只作为瞬时定性感知注入当前 user 消息尾部**（[brain.js:1018-1023](src/brain.js#L1018-L1023)）；
   - 绝不写入 `memory.history`，保持系统级提示词（System Prompt）逐字节稳定与 ~90%（实测累计 92.0%、300 轮均值 86.9%）的 KV Cache 命中率防线绝对不可动摇。
2. **零新增孤立状态机（No Spurious State Machines）**：
   - 严格遵循 [trigger.js:262-269](src/trigger.js#L262-L269) 禁令，严禁额外凭空捏造独立的 `mood` 状态机；
   - 心境慢变量（`warmth`, `stillness`）必须作为已有 `internal-regulation` 的扩展层运行，复用成熟的阻尼与快照机制。
3. **零数字泄露与主观不可达（Subject Inaccessibility）**：
   - 严格遵循 [internal-state.js](src/internal-state.js) 第 2 条铁律 `subjectAccessible = false`；
   - 严禁向模型注入任何工程数值（如 "你现在 energy=42"），只允许定性体感流动（如 "身体有些乏了，泛起淡淡的困倦"）。
4. **事件驱动与零轮询成本（Zero-Polling Event-Driven）**：
   - 严禁在主进程或渲染层启动任何常驻 `setInterval` 轮询心跳；
   - 阻尼衰减与状态演算严格绑定在已有物理事件节点：用户交互、窗口关闭（`updateOnWindowClose`）、夜间入睡与苏醒（`updateOnSleep`）。

### 阶段 2：v1.0.3（第二跃：心境慢变底色与昨夜余温 · 要素四 · 已落地）
* **定位**：引入具阻尼系数与迟滞回线的连续心境变量，告别瞬时即时应答，赋予数日维度的长程情绪惯性。
* **改动范围**：`src/internal-regulation.js`, `src/brain.js`, `test/internal-regulation.test.js`, `README.md`
* **终审确立机制（乙+丙 混合与墙钟连续动力学）**：
  1. **慢变层定义与认识论纯净性**：
     - 在 `REGULATION_BOUNDS` 扩展两个心境慢变量：`moodWarmth` 与 `moodStillness`（`[0, 100]`，默认基线 50）；
     - 严格不进入 `getState()` 内部标量集合（保持主体不越权与历史快照紧凑）；
     - `createSnapshotRecord()` 在平级附加 `payload.mood`，`InternalRegulationManager.replay()` 解析并输出 `finalMood`，保持 `finalState` 结构 100% 原始兼容；
     - 磁盘持久化通过 `load()` / `save()` 独立维护 `data.mood`，与底层生理标量清晰解耦。
  2. **真实墙钟连续衰减（Continuous Wall-Clock Decay）**：
     - 废除轮内衰减锯齿，全生命周期以 48h 物理半衰期（$M(t) = 50 + (M_0 - 50) \cdot 2^{-\Delta t / 48\text{h}}$）平滑向 50 回落；
     - 睡眠沉淀完全由真实生理睡眠时长自然推进（8h 自然保留 92.6%），取消离散 40% 双重打折。
  3. **关窗提示词基调锚定与平滑限幅（Slew-Rate Limiting）**：
     - 关窗小结增加 `moodTone: { warmth, stillness }` 提示词锚定（50 中性，68~80 温暖，20~32 疏离）；
     - 平淡窗口 LLM 省略 `moodTone`，系统走连续自然顺延衰减，杜绝硬跳回 50；
     - 显式注入应用 $\text{SlewMax} = 20$ 单窗最大速率限幅，兼顾稳态动态范围（可充至 81+）与防过激冲激。
  4. **感知滞回与机制缝隙保护（Hysteresis + 12h Hold-Off）**：
     - 采用非对称滞回区间：进入门限 62，退出门限 53；
     - 针对生产实测窗口跨度（4.3h ~ 86.9h+），增加 12h 退出延时保护机制（跌破 53 后若 12 小时内重新点亮则不熄灭），彻底消除换窗缝隙闪烁。
  5. **定性感知注入**：
     - 在 `formatPerception()` 中将滞回滤波后的心境底色（如“心绪温热而踏实”）以瞬时感知注入 user 消息尾部，严格恪守数字不可知红线与前缀缓存不变式。

  3. **架构边界与不变式坚守**：
     - 恪守 `trigger.js` 禁令：零侵入 `trigger.js`，避免跨进程 IPC 协议破坏与主动搭话队列竞争；
     - 恪守 `memory-dynamics.js` 纯计算定位：零 IO、无 `this.save()`，所有持久化收归 `Memory` 统一管理；
     - 保持 `currentSelfContext()` 纯读取无副作用。

### 关于要素二与要素三的范围与归宿决策（Scope & Roadmap Decision）
* **要素二（内在动机与独处欲 · 阶段 5.5 · v1.0.7 · 已落地）**：
  - **正反半轴正交互补**：正半轴（挂机问候 30min、好奇破冰 `curiosityAsk` 30min + 40min 节流、自发留痕 `wantToLeaveSomething` 120min、特质偏置 `computeInitiativeBias`）保持完备零改动；v1.0.7 补齐负半轴（高频密集打扰下的社交过载与独处退避边界）；
  - **终审确立机制**：
    1. **接通 `interactionDensity` 生理体感带**（`src/internal-regulation.js:formatPerception`）：对齐连戳 10/15 下（`10×4=40` / `15×4=60`，高于实机日常峰值 `33`），在 `>= 40` 输出中档节奏偏密体感、`>= 60` 输出重档过载散乱与委婉退避授权，随静默挂机自然消退；
    2. **连戳过载 `hint` 分级与 `× bias` 方向校准**（`src/trigger.js`）：新增 `POKE_OVERLOAD_THRESHOLD = 10`，采用 `overloadNeed = clamp(round(10 * bias), 10, 15)`。**刻意取舍（Trade-off）**：下界封底 10 下虽压制了高安静者的低端过载敏感度（`10×0.5=5` 被封底为与中立相同的 10 下），但换取了与 `interactionDensity >= 40`（`10×4=40`）的严格同步、彻底消除嘴身脱节；性格差异由 `pokeNeed` 与 `overloadNeed` 共同构成的轻度抗议缓冲窗口（喜静 `8~9` 下仅 2 下宽 vs 中立 `5~9` 下 vs 外向 `3~14` 下、15 下才过载）体现，且不挂无消费方的冗余布尔字段；
    3. **瞬时环境感知质性标注**（`src/tracker.js:snapshot`）：当本轮未消费 `clicks >= 10` 时附带 `（动作密集急促，节奏有些被打乱）`（**数字阈值与 10 统一，但时间尺度不同**：`trigger.js` 计 8 秒瞬时连戳窗口，`tracker.js` 计自上次对话以来的未消费累计值），保持既有正则子串兼容；
    4. **零行为状态机与零新引擎字段**：不碰 `desktop-motion.js`，不在 `TriggerEngine` 新增时间戳字段。
* **要素三（具身环境知觉 · 归入后续版本）**：
  - **用户拍板**：**不纳入 v1.1 版本范围，正式延后归入以后的版本（如 v1.2 跨平台与物理具身专项）**；
  - **决策依据**：经实测与量化评估，要素三涉及 Electron 主进程原生 API 侵入（`powerMonitor` / `nativeTheme` / `idleTime`）、出厂未通电的 `digitalUmwelt` 与 `attentionGate` 漏斗前置依赖、多平台系统事件差异以及本体论黑名单规避，属于重量级系统工程，延后是理智且负责的架构决策。
