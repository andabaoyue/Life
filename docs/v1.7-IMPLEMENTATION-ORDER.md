## 1. v1.7-a：STT 语音输入（中 / 英）

### 1.1 分步施工（共 5 步，每步可独立验收）

#### 第 1 步：可行性探测（**半天，决定后续全部路线**）

**目的**：确认 Web Speech API 在本仓 Electron 44 里到底能不能用。**这一步失败不代表项目失败，只代表走 B 档。**

建一个**临时**探测页 `_probe-speech.html`（施工完即删，不进 git）：

```html
<!-- 仅用于实测，验证后删除 -->
<script>
  const SR = window.SpeechRecognition || window.webkitSpeechRecognition;
  document.title = SR ? 'HAS_SR' : 'NO_SR';
  if (SR) {
    const r = new SR();
    r.lang = 'zh-CN';
    r.onerror = (e) => { document.body.textContent = 'ERR:' + e.error; };
    r.onresult = (e) => { document.body.textContent = 'OK:' + e.results[0][0].transcript; };
    r.start();
  }
</script>
```

在真实 Electron 窗口里加载它（不是浏览器），观察：
- `document.title` 是 `NO_SR` → **A 档直接排除**，走 B；
- 出现 `ERR:network` / `ERR:service-not-allowed` → **A 档不可用**，走 B；
- 出现 `ERR:not-allowed` → 是权限问题，先补 1.2 的权限处理器再试；
- 出现 `OK:...` → **A 档可用**，优先 A（零依赖、零密钥）。

#### 🔴 第 1 步已实测完成（2026-10-20）—— **结论：A 档排除，走 B 档**

**实测环境**：Electron 44.4.5（Chromium 152），Windows。

| 轮次 | 加载源 | `apiPresent` | `startError` | 说明 |
|---|---|---|---|---|
| 第 1 轮 | `data:` URL | `true` | **`not-allowed`** | opaque origin 直接被拒 —— **这是变量污染，不是真实结论** |
| **第 2 轮** | **`file://`（生产同源）** | **`true`** | **`network`** | **真实结论** |

**同时抓到权限调用链**（证明 handler 写法正确）：

```
[PERM-REQ] permission=media url=file:///<应用目录>/_probe-speech.html
```

→ 确认 `permission` 枚举就是 `'media'`，与 `electron.d.ts:13508` 一致；麦克风请求确实进入闸门。

**结论**：
1. `SpeechRecognition` **API 存在**（`apiPresent: true`），不是"没有这个 API"；
2. 但 `start()` 后立即以 **`network`** 失败 —— Chromium 语音识别依赖 Google 云端服务密钥，**Electron 构建不带该密钥**；
3. **A 档（Web Speech API）不可用，确定走 B 档（云端 Whisper 兼容）**。

> ⚠️ **方法论教训（写进本单，防后人重蹈）**：第一轮用 `data:` URL 得到 `not-allowed`，
> 若不排除这个变量，会误判成"权限没配好"而去改一堆权限代码 —— **那是白改**。
> 探测语音识别**必须用 `file://` 或 `http(s)://` 等有明确来源的上下文**，`data:` 的 opaque origin 会让结果失真。

> ⚠️ **另一条环境坑**：本机 shell 里 `ELECTRON_RUN_AS_NODE=1`，
> 直接 `electron xxx.js` 会让 `require('electron')` 返回 undefined（主进程模块全废）。
> 跑 Electron 主进程脚本时必须先清掉该变量（`cmd /c "set ELECTRON_RUN_AS_NODE=& electron ..."`）。

**因此第 3~5 步按 B 档推进，A 档相关分支不再实现。**

#### 第 2 步：权限闸门（**安全加固，与 A/B 档无关，必做**）—— ✅ 已落地（2026-10-20）

> **实测完成**：`installPermissionGate(session.defaultSession)` 已写入 `main.js`，
> 装在 `createWindow()` 之前。门禁 `test/v17-permission-gate.test.js` **23 项全绿**，
> 变异 **4/4 捕获**。以下为原始设计稿，保留作为判据说明。

`main.js` 的 `app.whenReady()` 内、创建任何窗口之前：

```js
// 🔴 v1.7-a：麦克风权限必须显式白名单。
//   Electron 在不设 handler 时对 permission 请求的处理不可依赖 ——
//   本仓此前无任何 handler（实测 grep 零命中），等于把"是否允许麦克风"交给了默认行为。
//   裁决：默认拒绝，只放行主窗口与对话窗的 media 请求。
session.defaultSession.setPermissionRequestHandler((wc, permission, callback) => {
  // ⚠️ 2026-10-19 审计核实：`electron.d.ts:13508` 的 permission 枚举里只有
  //   'media'，没有 'microphone' —— 后者仅出现在 `:14207` 的 askForMediaAccess
  //   （macOS 专用 API），不是 permission 枚举值。因此这里只判 'media'。
  //   写 `permission === 'microphone'` 会恒为 false，把麦克风请求一并拒掉。
  if (permission !== 'media') return callback(false);   // 其余权限一律拒（通知/地理位置等）
  const url = wc && wc.getURL ? wc.getURL() : '';
  callback(isAppLocalUrl(url));                          // 复用 ipc-guard 的本地页判定
});
session.defaultSession.setPermissionCheckHandler((wc, permission) => {
  if (permission !== 'media') return false;
  const url = wc && wc.getURL ? wc.getURL() : '';
  return isAppLocalUrl(url);
});
```

> ⚠️ `isAppLocalUrl` 已在 `src/ipc-guard.js` 的 `module.exports` 中导出，**直接复用，不要另写一份本地页判定**。
>
> ⚠️ **Node 侧还有一个坑**：`setPermissionCheckHandler` 的 `webContents` 参数**可能是 `null`**（检测在请求之前发生）。所以两个 handler 都必须容忍 `wc` 为空 —— 上面对 `wc` 做了 `wc && wc.getURL` 的守卫，**不要简化成 `wc.getURL()`**。

### 1.2 铁律（违反即打回）

1. **识别结果必须经用户确认才发送。** 断言方式：静态扫描 `chat.js` / `pet.js`，识别回调里**不得出现** `api.send`（有独立断言，防"顺手自动发送"）。
2. **音频绝不落盘。** 采集到 buffer 后只在内存里转手；`MediaRecorder` 的 `blob` 不写文件。门禁：跑完 STT 后临时目录无新增音频文件。
3. **权限默认拒绝。** 非 `media` 权限一律 `callback(false)`；非本地页一律拒。
4. **失败静默。** 任何错误只显示一行客观提示（`ui-i18n` 键），**不弹 Modal、不动对话流**。
5. **不改 `brain.js` / `memory.js` / `trigger.js` / `subject-state.js` 一个字节。**
6. **STT 凭据与对话凭据物理隔离。** 断言：`stt-transport.js` 的入参里**不得出现** `connections` 模块的任何对象；STT Key 存独立字段，**不得回退到对话 Key**。
7. **未配置时置灰，不是点了才报错。** 断言：配置缺失时 `#micBtn` 带 `disabled`。

### 1.4 验收判据

1. 中文一句 → `#input` 出现中文；英文一句 → 出现英文；**均不自动发送**（有断言）。
2. 权限被拒 → 一行 `stt.denied`，不抛、不弹窗，对话功能不受影响。
3. 断网 / 密钥无效 → `stt.failed`，静默降级。
4. **音频零落盘**（临时目录断言）。
5. **历史零污染**：STT 前后 `memory.build()` 的 system 与 history 快照逐字节相等。
6. 权限处理器：未列入的权限全部 `false`（独立断言）；`wc` 为 `null` 时不抛。
7. **凭据隔离**：未配置 STT 时，`stt-transport` 拿不到任何对话凭据；`#micBtn` 处于 `disabled`。
8. 全量套件 0 FAIL；`docs.test.js` 项数对账通过。

### 2.2 铁律
