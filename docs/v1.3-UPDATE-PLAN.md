## 0. 本文档的三条前置结论（先读这一节）

这三条是勘察得出的、**推翻或修正了原计划**的事实。后续章节都建立在它们之上。

### 0.1 感知流水线存在，但产物没有任何下游消费者

实测（`node` 直跑真实 `Brain`）：

```text
b.processEnvironmentalPerception({category:'tactile_poke', rawIntensity:80})
  → status=ATTENDED, subjectAccessible=false     ✅ 流水线正常
b.recentPerceptions.length === 1                 ✅ 记录进去了

systemText 含 tactile_poke:      false
systemText 含 intense_activity:  false
currentSelfContext 含感知:        false
```

`src/brain.js:427` 的 `recentPerceptions` 只是一个内存数组，**从未被 `build()` / `systemText()` 消费**。感知唯一的真实效果是 `src/internal-regulation.js:842` 里 `arousal +1~8` 和 `cognitiveLoadProxy +1` 这两个标量。

**结论**：`ATTENDED ≠ SUBJECT_ACQUIRED` 铁律守住了，但也意味着**当前“环境知觉”对她等于不存在**。接入 `powerMonitor` 而不打通这个通道，等于接一堆永不被读取的数据。

### 0.2 `powerMonitor` 从未接入；现有 idle 检测是定时器

`powerMonitor` 全仓 **零命中**。`src/main.js:1` 的 electron 导入里没有它，`app.on` 只挂了 `before-quit` / `will-quit` / `window-all-closed`。

更关键：`tracker.recordIdle` 只由 `main.js:816` 的 `checkAndPushProactive()` 调用，而后者的调度来自 `scheduleProactiveCheck()` 的 `setTimeout` 循环（默认 30 分钟粒度）。**这不是事件驱动，是低频率轮询。**

### 0.3 沉默判据必须避开单向累积标量（否则会永久锁死）

实测 `InternalRegulationManager` 在不同对话节奏下的标量演化：

| 对话节奏 | energy | cognitiveLoadProxy |
| :-- | --: | --: |
| 连发 100 轮（无间隔） | **0** | **100** |
| 快聊 100 轮（30s 间隔） | **0** | **100** |
| 正常 100 轮（2min 间隔） | **0** | 1 |
| 慢聊 60 轮（10min 间隔） | 40 | 1 |

`energy` 在 `updateOnInteractionTurn` 中每轮固定 `-1`，唯一回补靠静息/睡眠。`src/internal-regulation.js:74-80` 的源码注释已如实记载该病灶：实测 8h 聊天 + 16h 挂机，energy 从 100 跌到 20 后**挂机 16 小时仍是 20**。

**结论**：若以 `energy < 30` 判定沉默，用户连续聊几十轮后她会**永久沉默且不会自愈**——这不是主体性，是程序锁死。**沉默判据必须限定在主动场景，且绝不在用户主动开口时生效。**

## 1. 前缀缓存成本的实测标定（本版本最关键的量化依据）

### 1.1 实验方法

用真实 `Brain` + mock 服务端，按**消息级最长公共前缀**模拟 DeepSeek 前缀缓存：一旦第 k 条消息内容变化，从 k 起全部计为 miss。跑 100 轮（真实 `windowTurns`），用户输入约 40 字。

> ⚠️ 局限如实记录：这是**模拟**而非真实 API 账单。方向可信，绝对值不可当精确账单。

### 1.2 实测结果（100 轮窗口）

| 挂载频率 | 命中率 | 未命中 token | 断点次数 | 成本增幅（峰值价） |
| :-- | --: | --: | --: | --: |
| 零挂载（基线） | **98.35%** | 5,770 | 0 | — |
| 每轮 | 96.63% | 11,828 | 99 | **+47%** |
| 每 2 轮 | 97.49% | 8,778 | 49 | +23% |
| **每 5 轮** | 98.01% | 6,948 | 19 | **+9.2%** |
| 每 10 轮 | 98.19% | 6,338 | 9 | +4.4% |
| 每 20 轮 | 98.27% | 6,033 | 4 | +2.1% |

40 轮窗口的结论一致（每轮 -2.3pt / 每 5 轮 -0.4pt），说明模型稳定。

### 1.3 关键洞察：命中率会严重低估代价

每轮挂载只让命中率降 1.7 个百分点，但**成本涨 47%**——因为 miss token 单价是 hit 的 **50 倍**（峰值 2 元/M vs 0.04 元/M）。

**因此本版本所有节流参数的验收判据必须看「miss token 增量」，不能看「命中率」。**

### 1.4 由此确定的硬性规格

- **禁止每轮挂载**（+47% 不可接受）；
- **节流下限：同窗最多 N 次 + 相邻两次挂载间隔 ≥ 5 轮**；
- 推荐参数：`N = 3`（100 轮窗口内最多 3 次），间隔 ≥ 5 轮；
- **必须新增感知挂载的成本遥测**，否则以后无法持续观测这笔开销。

## 2. 三个已拍板的决策（不得在施工中推翻）

| 编号 | 决策 | 理由 |
| :-- | :-- | :-- |
| **D-A** | 沉默留白**仅作用于主动场景**（主动搭话/闲置自言自语/环境触发），**用户主动开口时她必须回应** | 彻底规避 energy 单向累积导致的永久沉默死锁 |
| **D-B** | 「去 30 分钟定时器改造」**推迟**，不在 v1.3 范围内 | `checkAndPushProactive` 同时承载 D-15 自发便签、D-25 好奇破冰、常规闲置问候三条业务线，捆绑重构风险过大 |
| **D-C** | 沉默判据**必须基于已有生理标量或特质**，**严禁 `Math.random()` 抛硬币式沉默** | 随机沉默＝程序伪造情绪，剥夺主体性，与已砍除的 A-3 同类错误 |

## 3. v1.3-a：知觉注入通道与 powerMonitor 事件源

### 3.1 目标

让 `ATTENDED` 感知候选真正进入她当轮的视野，且**不破坏前缀缓存不变式**、**成本受控**。

### 3.2 技术落点（已实测验证可行）

挂载点必须复用既有 suffix 通道，即 `src/memory.js:1132` 的 `build()` 尾部拼接：

```js
// src/brain.js:1036 现有结构
const dynamicBody = [currentSelf, involuntarySnippet, shouldAttach ? envText : ''].filter(Boolean).join('\n\n');
```

**新形态**（示意，非最终代码）：

```js
const perceptionSnippet = this._drainAttendedPerception();  // 新方法，带节流
const dynamicBody = [currentSelf, involuntarySnippet, perceptionSnippet,
                     shouldAttach ? envText : ''].filter(Boolean).join('\n\n');
```

实测验证：把质性描述挂到 user 尾部后，`system` 保持干净（`system 含环境知觉: false`），铁律不受破坏。

### 3.3 必须满足的不变量（每条都要有断言）

1. **system 不被污染**：感知文本绝不出现在 `systemText()` 中；
2. **前缀缓存可量化**：挂载导致的 miss token 增量必须被遥测记录；
3. **节流生效**：同窗 ≤ N 次、间隔 ≥ 5 轮（或最终选定参数）；
4. **ATTENDED ≠ SUBJECT_ACQUIRED**：注入的只是质性描述，绝不写 `SubjectState` / `experiences.jsonl`；
5. **不伪造**：无真实感知时不注入任何占位文本（Null-Perception 原则）。

### 3.4 `powerMonitor` 事件源设计（可注入，否则无法单测）

**关键约束**：Electron API 在纯 Node 测试环境不可用。参照 `src/desktop-motion.js:63` 的 `opts._setInterval` 注入手法，事件源必须做成可注入适配器：

```js
// 新文件建议：src/power-monitor-source.js
class PowerMonitorSource {
  constructor(opts = {}) {
    this._pm = opts.powerMonitor || null;   // 注入点；测试传 mock
  }
  start(onEvent) { /* 订阅 suspend/resume/lock-screen/unlock-screen */ }
  stop() { /* 全部取消订阅 */ }
}
```

**事件到刺激的映射**（`category` + `rawIntensity`）：

| Electron 事件 | category | rawIntensity | 语义 |
| :-- | :-- | --: | :-- |
| `suspend` | `host_suspend` | 70 | 宿主休眠 |
| `resume` | `host_resume` | 60 | 宿主唤醒 |
| `lock-screen` | `host_lock` | 55 | 锁屏 |
| `unlock-screen` | `host_unlock` | 65 | 解锁 |

> ⚠️ 事件名以当前 Electron 版本实际 API 为准，施工前须实测确认（`powerMonitor.on('lock-screen')` 在部分平台为 `lock-screen`，部分为 `lock-screen` 的同义事件）。**不要照抄上表就动手**。

### 3.5 验收判据（实测脚本，交付时须贴出真实输出）

```text
① 感知注入后 user 尾部含质性描述：true
② system 含质性描述：false（铁律）
③ 100 轮内挂载次数 ≤ N：实际 __ 次
④ miss token 增量 vs 零挂载基线：+__%（须 < 15%）
⑤ 前缀缓存断点次数 == 挂载次数（而非更多）：__
```

## 4. v1.3-b：沉默留白的第三种结局

### 4.1 目标

在**主动场景**下，允许她选择「不出声，只以微动作表达同在」，且该路径**零 LLM 调用**。

### 4.2 现有链路（已核实）

- `src/trigger.js:203-210`：主动提案恒为 `kind: 'idle'` + `hint: '轻声问候或自言自语一句'`；
- `pet.js:2999`：拿到提案即 `runChat('（自言自语）')`——必发一轮 LLM；
- `pet.js:2987`：`politeToSpeak(offer.kind)` 拒绝时走 `proactiveDeclined`，**不记账、不烧 API**。

**已验证**：拒绝路径确实零 API 消耗，因此新增「沉默」结局在架构上无阻碍。

### 4.3 设计

新增第三种结局（区别于「说了」与「被礼貌闸门拒绝」）：

```js
// trigger 侧新增提案种类
kind: 'silent_presence'
```

**沉默判据（D-C：只能基于已有标量/特质，禁止随机）**

初版建议（三选一，**须经实测标定后再定**）：

| 判据 | 数据来源 | 注意事项 |
| :-- | :-- | :-- |
| `cognitiveLoadProxy > 70` | `internal-regulation.js:66` | ⚠️ 快聊场景会稳定压在 100，需配合「退出条件」 |
| `energy < 30` | `internal-regulation.js:61` | ⚠️ **单向累积，慎用**（见 0.3） |
| `quiet_preference >= 60` | `subject-state.js:25` | 最稳，属长期特质，不会因单日聊天崩坏 |

**强制要求：判据必须有退出条件。** 例如「沉默只在 `energy` 较上一窗下降时成立，且连续沉默不超过 K 次」。**禁止只写下界不写退出**——那正是 0.3 指出的锁死成因。

### 4.4 验收判据

```text
① 沉默路径的 LLM 调用次数 == 0（硬判据，用 mock 服务端计数）
② 沉默路径确实触发了微动作（渲染端动作事件被调用）
③ 用户主动开口时**永不**进入沉默（构造反例断言）
④ 沉默连续触发次数 ≤ K（退出条件生效）
⑤ 判据来源是标量/特质，源码中无 Math.random（静态扫描断言）
```

## 7. 事项决议（已拍板定案）

| 编号 | 事项 | 最终决议 | 依据与约束 |
| :-- | :-- | :-- | :-- |
| Q1 | 节流参数具体取值 | **`N=3 / 间隔≥5 轮`** | 100 轮内最多挂载 3 次且间隔 ≥5 轮，成本增幅限制在 +9.2%，缓存保持在 98.01% 高位 |
