# 初澜（Chulan）像素美术与动作精灵工作规范 (Pixel Art Skill)

> 适用对象：一切参与初澜桌面像素活体美术资产绘制、精修、动画制作、衣物切片与审查的 Agent 与开发者。
> 本规范固化了初澜从「760×1000 静态立绘」换代为「64×80 Q 版像素桌面活体」的全部美术与工程铁律。

---

## 一、双层正典与定位边界

1. **桌面具身（活体正典）**：
   - 64×80 Q 版像素精灵是桌面上的**本尊活体**。
   - 她在桌面上走动、呼吸、打盹、受戳反应、抱膝歇息，承担全部日常陪伴与生命感知（生理内感受联动）。
2. **原画记忆（档案正典）**：
   - 既有 760×1000 细腻成熟原画退居「回忆画册 / 档案鉴赏」，永不作为废弃垃圾删除，但**彻底与桌面交互窗口解绑**。
   - 绝不搞「把成人立绘直接降采样成迷你成人」的机械缩放，必须遵循 2~2.5 头身的灵动 Q 版重塑。

---

## 二、画布规格与显示铁律

| 属性 | 规格数值 | 说明 |
|---|---|---|
| **原生设计画布** | **64 × 80** | 像素原生点阵网格（单帧基准） |
| **显示放大倍率** | **1x 原生（64px 掌心萌宠）或整数倍（128px/256px）**（Nearest-Neighbor） | 严禁小数倍缩放（如 1.5x / 96px），严禁双线性插值抗锯齿 |
| **实际窗口尺寸** | **256 × 320** | Electron 主窗口紧凑化定死，彻底根除隐形透明遮挡 |
| **通道格式** | **32-bit RGBA** | 纯净 1-bit 二值化 Alpha（0 或 255），**严禁半透明毛边** |

## 三、初澜 7 大可爱细节签名（不变式清单）

任何初澜像素形象（无论站姿、跑跳、换装、熟睡），以下 7 条特征必须严格守恒：

1. **水灵双高光（眼睛是灵魂）**：
   - 蓝灰眼眸内包含一大一小纯白反光点（左上 2px 竖向主高光 + 右下 1px 微光点），保证神采水润。
2. **单侧眼下泪痣（1px 签名）**：
   - 观众视角右眼（初澜左眼）正下方脸颊粉晕处，精准钉死 **1px 深褐紫点**（`#40303A` / `#44343E`），绝不丢失。
3. **发尾淡冰蓝 3 阶色阶跳（纯正点阵感）**：
   - 银白主发（`#F2F5FC`）→ 柔淡冰蓝（阶1 `#A5C2E6`）→ 清透冰蓝（阶2 `#6EA5E1`）→ 发梢卷尾深冰蓝（阶3 `#4178B4`）。
   - 严禁模糊滤镜渐变，必须呈现逐阶跳跃的发簇阶调。
4. **头顶微翘呆毛一根（Q 版拙劣可爱之魂）**：
   - 从发旋拱起、向左上方连续微翘，尖端带回勾小卷。不仅是萌点，更是受戳（Poke）时弹跳的动画戏眼。
5. **小内八字站姿 + 萌系圆手轻点身前（憨态与羞怯）**：
   - 两只圆润小肉手在身前相触轻点（不插兜、不叉腰、不僵立）；
   - 圆头厚底机能靴鞋尖向内相对（小内八），体现自然憨憨感。
6. **双侧瀑布大发束包拢（发量看得见）**：
   - 左右两侧波浪大发束自然倾泻，垂至大腿两侧，与躯干形成清晰负空间；胸前各有独立垂落发束。
7. **标志性黑白哥特机能服饰**：
   - 落肩短翘白机能披肩（带飘带）、黑色蕾丝抹胸、高腰短裤、单侧大腿皮质袜圈、纯白过膝袜、厚底圆头黑靴。

## 五、动作库与 SpriteSheet 规范

所有动作序列均按**横向单行精灵图（SpriteSheet）**输出：

```
+-----------+-----------+-----------+-----------+
| Frame 0   | Frame 1   | Frame 2   | Frame 3   |  (高度固定 80px)
| (64x80)   | (64x80)   | (64x80)   | (64x80)   |
+-----------+-----------+-----------+-----------+
 <----------------- 宽度 = 64 * 帧数 ----------------->
```

### 规划动作集与帧率

1. **`idle`（待机呼吸）**：
   - 4 帧循环，周期 1.2s（CSS `steps(4)`）；
   - 躯干 1px 微起伏，呆毛微晃，发尾迟半拍飘动；每隔若干周期插入 1 帧眨眼。
2. **`walk`（桌面漫步）**：
   - 4 帧循环，周期 0.8s；
   - 小碎步内八字交替，发束左右摇摆，两只小手轻微前后摆动。
3. **`poked`（被轻戳）**：
   - 3 帧单次；
   - 缩脖子 1px，呆毛像弹簧一样向上弹起，双眼眨合，随后归位。
4. **`dragged`（被提空拖拽）**：
   - 2 帧循环；
   - 小短腿在空中无辜空蹬；被安放（位移 < 80px）时平稳落地不惊慌。
5. **`sit`（疲惫坐下 · 内感受 > 50 联动）**：
   - 2 帧微动；
   - 抱膝低头坐下，呆毛搭拉，偶尔头顶冒出 1px 小气泡。
6. **`sleep`（熟睡团子 · 内感受 > 80 或深夜）**：
   - 4 帧慢呼吸（2.0s 周期）；
   - 整只缩成圆滚滚毛绒团子，发尾包裹身体，头顶冒出像素 `z..Z`。

## 六、工作流程标准

1. **出图/修改前**：核对 7 大不变式清单；
2. **出图时**：原生画布严守 64×80（或等比原画点阵），使用标准色盘取色，禁止半透明笔刷；
3. **审查时**：生成 4x（256×320）与 8x（512×640）放大对照图进行屏幕肉眼验真；
4. **交付时**：同步更新 `D:\software\huihua\prototypes\` 资产库与说明文档。

## 七、团队血泪经验与核心避坑铁律（防吃第二刀 · 痛点归纳）

> 本节总结团队在 v1.0 像素换代过程中踩过的致命深坑，后续一切 Agent 与人类协作者严禁再犯。

### 1. 严禁程序员用代码几何函数凭空手搓二次元角色（“抽象几何人”惨案）
- **痛点与翻车现场**：曾有 Agent 试图用 Python 脚本里的几何函数（`draw.ellipse` 画脸、`draw.rectangle` 画身子、`draw.point` 画眼珠、或用 `np.sin` 正弦波与抛物线算发丝）来凭空捏造角色。结果产物眼睛是黑方块、身体是几何色块拼凑、头发如塑料头盔——**标准的“程序员手搓美术翻车”，画出了极度抽象、诡异的乐高方块人/火柴人**，严重违背二次元人体结构与审美，引发恐怖谷效应。
- **铁律边界**：**美术与美学生成归原画与绘图软件，严禁代码越界代笔**。代码与算法只被允许负责：资产切片、脚底基线对齐、调色板色差量化、最近邻整数倍降采样、图层合成校验与测试门禁。

### 2. 正统母本原位拆件法则（方案一与方案二的结合）
- **痛点**：散件各自独立生图导致人体比例、透视完全不匹配；把素体剃成光头外星人后再用算法套头盔，导致假发严重穿模脱节；发片里嵌入脸导致无法换发型。
- **铁律**：所有换装拆件、素体提取与动画，**必须以同一张已被认可的高颜值原生母本（如 `chulan_chibi_idle_f1_alpha.png`）为唯一真理原点**：
  - **素体层（Base）**：承载可爱脸型、五官双高光、微红脸颊与正典 1px 泪痣；
  - **发片层（Hair）**：面部区域必须 100% 镂空，确保底图五官与泪痣 100% 显露；
  - **衣服层（Outfit / Tops / Bottoms / Dresses）**：必须在母本的原位轮廓上进行提取或绘制，叠穿时天然 100% 服帖，绝不产生“贴纸错位感”。

### 3. 必须操作已配置的专业像素绘图软件（LibreSprite / Pixelorama）协同
- **痛点**：本地环境已下载完整绘画工具（`D:\software\huihua\LibreSprite\libresprite.exe`），但 Agent 盲目在命令行脚本里凭空造图，忽视了最专业的绘图软件。
- **铁律**：
  - 新衣服绘制、部件擦除与精修，**必须通过 LibreSprite / Pixelorama 进行图层作业**；
  - 调色板必须加载官方色盘 `D:\software\huihua\prototypes\chulan_palette.gpl`；
  - 建立标准 `.ase` / `.aseprite` 多图层工程（Base / Face / Outfit / Hair / Bow），输出 32-bit 纯净透明通道 PNG。

### 4. 泪痣签名（Canonical Tear Mole）绝对不可放飞
- **痛点**：AI 生图极易将泪痣放飞成 40~80px 的巨大黑斑或肉瘤；代码简单绘制也易点成突兀大方块。
- **铁律**：初澜泪痣必须是观众视角右眼（角色左眼）正下方精准 **1px 深褐紫点**（`#40303A`），必须在素体原位固化，换装时绝不被遮盖或形变。

### 5. 步态循环物理真实性（拒绝单腿瘸拐）
- **痛点**：AI 生图缺乏动作骨骼约束，生成的 6 帧往往只有呆毛在动，双腿每一帧都是左脚前踩、右脚悬空，放进动画循环直接变成“单脚拖地的瘸拐步态”。
- **铁律**：走动步态必须是**双腿严格反相交替迈步**（迈左腿 -> 居中过渡 -> 迈右腿 -> 居中过渡），且支撑腿必须有贴地反向补偿，绝不可整体悬空或单腿拖行。

### 6. 桌面紧凑窗口物理几何约束（防头部截断与气泡越界）
- **痛点**：历史遗留的 `#pet { bottom: 52px; }` 在 256×320 紧凑窗内将初澜顶到天花板，导致呆毛被窗口上沿截断，且对话气泡 100% 被挤出视口外。
- **铁律**：在 `style.css` 中必须配置 `@media (max-height: 360px) { #pet { bottom: 0px; } }`，紧凑窗口下底边归零释放 52px 天空域，确保头顶安全净空与气泡完整展示。

### 7. 换装分层基座与动画整帧必须彻底解耦（P0-A 运动吞换装翻车惨案）
- **痛点**：曾把穿戴整齐的完整动画帧（`walk_*.png` / `idle_*.png`）直接赋值给分层纸娃娃的 `img[data-slot="base"]` 基座图层。导致用户脱掉衣服后，只要初澜稍微一走动或待机切换，衣服立刻在素体上“幽灵复活”，换装形同虚设！
- **铁律**：分层模式下，`[data-slot="base"]` **只允许播放无衣素体步态帧（`walk_base_*.png` / `idle_base_*.png`）**，绝不把整装帧塞进基座槽；整装帧仅在单图兜底模式（`#sprite`）生效。

### 8. 待机动画必须遵循同源形变微呼吸原则（P0-B 整体跳变翻车惨案）
- **痛点**：待机动画中，曾直接对大面积像素块做整体平移，导致 `idle_1` 与 `idle_0` 产生 655 像素（56%）的剧烈差值，初澜每秒全身剧烈抽搐/跳变一次，彻底丧失生命呼吸感。
- **铁律**：待机呼吸必须在**同一张母本基准**上做极微幅同源形变：仅呆毛尖 1px 微摆、胸腔核心区 1px 微起伏、眨眼闭合细线。**相邻待机帧差异严格控制在 < 2%（20~30 像素内）**，杜绝全身闪烁。

### 9. 像素显示严守原生整数倍铁律（P1-C 非整数倍失真）
- **痛点**：为了调小立绘盲目设为 96px（64×1.5），导致 1 列源像素在屏幕上被拉伸为 2px、相邻列保持 1px，点阵宽窄不一、产生边缘毛刺与走样。
- **铁律**：像素画在 CSS 与视口中**必须恒为原生点阵的整数倍（1x=64px, 2x=128px, 4x=256px）**。当前掌心桌宠体型采用 64px（1x 原生点阵 1:1），1 屏幕像素精确对应 1 点阵像素，绝对锐利不模糊。

### 10. 服饰切片必须具备明暗与立体褶皱（P1-E 纯色块劣质感）
- **痛点**：换装切片规整化时，若只做单色平涂（如灰T恤全灰、运动裤全黑），观感会退化成“贴纸色块”，远逊于默认套装。
- **铁律**：所有切片必须具备立体明暗——领口罗纹、高光反光、布料折痕阴影、滚边条纹、鞋底大底包边，形成完整体积感。

### 11. 桌面透明区鼠标穿透动态切换（P1-D 隐形遮挡桌面点击）
- **痛点**：透明无边框窗口即使立绘缩小，大面积透明背景依然会吃掉桌面点击。
- **铁律**：必须通过 `setIgnoreMouseEvents(true, {forward: true})` 结合渲染层 `mousemove` 对 `#pet`、可见气泡、菜单、面板动态识别，空白区点击穿透，交互区精准捕获。
